# version13 방법 정리

PR #91(B의 실제 팀 코드, `backend/src/msds/preprocess/layout.py`)의 **recursive XY-cut 읽기순서 복원**을 기본 추출 방법으로 쓰고, image+txt 출력 형태(layout.py 자체 포맷이 아니라 우리 방식)를 유지하면서, **layout.py의 선표 인식이 실패했을 때만 Docling TableFormer를 보조로 투입**하는 버전.

## 왜 만들었나

- version2~12까지는 전부 **"PDF 텍스트/Paddle 결과를 y좌표 근접도로 줄 묶기"**라는, 우리가 직접 만든 비교적 단순한 방식이었음.
- `docs/c/2026-10-30_PR91_텍스트추출_방법정리.md`에서 확인했듯, 팀의 실제 메인 브랜치(PR #91)는 **재귀적 XY-cut**으로 레이아웃 자체를 분석해서 읽기 순서를 복원하고, 줄바꿈된 칸 값을 이어붙이는(`join_wrapped`) 등 훨씬 정교한 방법을 이미 갖고 있었음.
- 이 방법을 그대로 가져다 쓰되, **출력 형식만 우리 컨벤션**(`pNNN.png`+`pNNN.txt`, `L001` 줄번호, 표는 `|` 묶음)으로 유지하고, 표 부분은 version12처럼 Docling으로 한 번 더 보강.

## 코드

- 파일: `backend/scripts/ocr_batch_version13.py`
- `backend/src/msds/preprocess/layout.py`의 `char_items()`, `page_tables()`, `reading_order()`, `_inside()`를 그대로 import해서 사용 (PR #91 코드 그대로, 재구현 아님)
- 사용법:
  ```
  uv run python3 backend/scripts/ocr_batch_version13.py --doc-id T21-025
  uv run python3 backend/scripts/ocr_batch_version13.py --output-version version13   # 전체 20건
  ```

## 동작 순서 (페이지 단위)

1. **텍스트층이 정상인 문서**: `layout.char_items(page)`로 글자 좌표를 재조립하고, `layout.page_tables(page)`로 PyMuPDF가 찾은 선표 좌표를 가져옴
2. **텍스트층이 없는 문서**: PaddleOCR 결과를 `layout.py` 조각 형식(`{"text","box"}`)으로 변환해서 같은 파이프라인에 태움
3. **Docling 표 감지**: 텍스트층이 정상인 문서만, 같은 PDF를 Docling TableFormer(GPU)로 변환해 표 그리드를 감지
4. **"이미 처리된 영역" 계산** (`covered_by_layout_tables`): `layout.page_tables()`가 선 정보로 이미 찾은 표 영역 안의 조각들을 전부 표시해 둠 — 이 영역은 `layout.reading_order()`의 `_table_rows`가 이미 칸 순서대로 올바르게 묶어주므로 손댈 필요가 없음
5. **표 매칭** (`match_table_to_items`): Docling 표의 셀 텍스트가 조각들과 정규화 후 70% 이상 일치**하고**, 매칭된 조각의 과반이 "이미 처리된 영역"에 **속하지 않을 때만** 채택. 즉 **Docling은 PyMuPDF가 표 자체를 아예 못 찾은 경우(테두리 없는 표 등)에만 보조로 투입됨**
6. **본문 생성**: 매칭된 표 조각을 제외한 나머지를 `layout.reading_order()`에 넣어 XY-cut 읽기순서 줄을 만듦
7. **표 포맷 통일**: `layout.py`가 자체적으로 처리한 선표도, Docling이 보조로 채운 표도 **전부 우리 컨벤션대로 `|`로 join**해서 출력(`_table_rows`가 남겨두는 `parts`를 이용해 layout.py의 기본 공백 두 칸 포맷을 `|`로 재구성)
8. **병합**: 전체를 y좌표로 재정렬 후 `L001...` 줄번호 부여

## version12와 다른 점

| | version12 | version13 |
|---|---|---|
| 표 아닌 본문의 읽기 순서 | 우리 코드의 y좌표 행 묶기(`entries_to_text`) | **PR#91의 recursive XY-cut**(`layout.reading_order`) |
| 줄바꿈된 칸 값 이어붙이기 | 없음 | **있음**(`layout.join_wrapped`) |
| Docling 개입 조건 | 70% 이상 매칭되면 항상 교체 | **70% 이상 매칭 + layout.py가 그 표를 아예 못 찾았을 때만** 교체 (폴백 전용) |
| 표 포맷 | 전부 Docling 그리드 or 우리 y좌표 묶기, 둘 다 `|` | layout.py 자체 처리분도 `|`로 재포맷해서 일관성 유지 |

## 결과 (20개 문서, 241페이지 전체 실행)

- Docling이 감지한 표 **75개 중 11개만 교체**(폴백 적용 전엔 66개였음) — 나머지 64개는 `layout.page_tables()`가 이미 정확히 처리하고 있어서 손대지 않음
- Docling이 실제로 개입한 문서: T21-014(5개), T21-S014/M013/006/010/039/045(각 1개)
- T21-002 p002(이전 version10/11에서 "표 인식 실패"로 결과가 나빴던 페이지)도 이제 긴 문장이 `join_wrapped`로 자연스럽게 이어짐

### 처리 시간 (타이밍 버그 수정 후 최종 재측정)

| 구간 | 시간 |
|---|---|
| 전체 문서 처리 시간(20개 문서 `document_total_seconds` 합) | 109.85초 |
| 그중 Docling 표 감지 시간 | 39.35초 |
| 평균 | 0.456초/페이지 (241페이지) |
| 표 감지/매칭 (최종) | 75개 감지 / **11개 매칭** |

텍스트층이 없어 PaddleOCR을 돌려야 하는 문서(T21-043, T21-S003)는 페이지당 약 1.0~1.1초로, 텍스트층 있는 문서(페이지당 0.15~0.3초)보다 훨씬 느림.

### version12 대비 속도

| | version12 | version13 |
|---|---:|---:|
| 전체 처리 시간 | 274.33초 | **109.85초** |
| 평균/페이지 | 1.138초 | **0.456초** |
| Docling 표 감지 | 34.66초 | 39.35초 |
| 표 감지/매칭 | 75 / 68 | 75 / 11 |

version13이 **2.5배 빠른 이유**: version12는 텍스트층이 있어도 모든 페이지에서 PaddleOCR을 돌리는 반면(version9 방식 그대로 유지), version13은 텍스트층이 정상이면 PaddleOCR을 아예 안 돌리고 `layout.char_items()`(PDF 글자 좌표)만 사용하기 때문. 매칭 수가 68→11로 줄어든 건 품질 저하가 아니라, "layout.py가 이미 잘 처리 중인 표는 안 건드린다"는 더 보수적인 규칙으로 바꾼 결과(위 "동작 순서" 5번 참고).

> ⚠️ **타이밍 버그 수정 이력**: 처음엔 `document_started` 타이머가 Docling 호출 **이후**에 시작돼서 `config.json`의 `document_total_seconds`에 Docling 시간이 전혀 안 잡히는 버그가 있었음. 타이머를 Docling 호출 전으로 옮기고, `docling_table_detection_seconds` 필드를 별도로 추가해서 지금은 둘 다 정확히 기록됨(version12도 같은 버그가 있어서 함께 수정).

## 한계 / 참고

- `layout.char_items`는 main 브랜치의 실제 운영 코드라서, 계속 업데이트될 수 있음(현재 `PREPROCESS_VERSION = "2026-10-29-wrap-mincol"` 기준) — main이 업데이트되면 이 스크립트도 자동으로 최신 로직을 타게 됨
- 텍스트층이 없는 문서는 PaddleOCR 결과를 그대로 XY-cut에 넣는데, PR#91 원본(`source.py`)의 "텍스트층 vs OCR 신뢰도 비교" 로직은 적용하지 않음 — 우리는 manifest의 `text_layer` 컬럼으로만 텍스트층 신뢰 여부를 결정(기존 버전들과 동일한 단순화)
- Docling의 PDF 전체 변환 방식 특성상, 표 감지 시간은 페이지 단위가 아니라 **문서 단위로만** 측정 가능함(version11과 동일한 제약)
