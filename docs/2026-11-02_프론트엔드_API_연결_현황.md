# MSDS 프론트엔드·추출 API 연결 작업 현황

2026-11-02 기준

문서 올리기부터 2.2 추출값 확인까지 API에 연결했고, 2.3·2.4 판정과 3 저장은 아직 자리 표시입니다. 지금 새 문서를 추출할 수는 없습니다. 모델 서버(RunPod)에 접속되지 않기 때문입니다.

- **바로 막힌 것 1:** Pod의 SSH 포트 11376이 연결을 거부해 터널이 끊겼습니다. 새 접속 명령어가 있어야 합니다.
- **바로 막힌 것 2:** 켜져 있는 8020 서버는 검수 API가 추가되기 전에 시작한 프로세스입니다. 다시 켜기 전에는 2.2 화면이 오류를 냅니다.
- **가장 큰 품질 문제:** 6항처럼 추출되지 않은 내용은 2.2에서도 채울 수 없습니다.
- **커밋:** 추출 화면까지는 `e/review-contract`에 커밋되어 있습니다. 2.1·2.2와 검수 API는 커밋하지 않았습니다.

## 완료한 작업

추출 결과를 항별로 저장하고, 화면에서 진행 상황·재생성 문서·검수 기록을 다룰 수 있게 했습니다.

| 영역 | 한 일 | 커밋 |
| --- | --- | --- |
| 프론트 설정 | `NEXT_PUBLIC_API_BASE`로 서버 주소 지정 (`.env.example`, `.env.local`) | 일부 |
| 항별 결과 저장 | 항이 끝날 때마다 원자적으로 저장, `GET /sections/{m}/{no}`로 조회 | 됨 |
| 재생성 문서 | TO21 제공 스크립트로 항별 분할, `GET /regenerated` | 됨 |
| 다시 시도 | 실패·중단 문서를 원자적으로 대기열에 재등록, 화면에 확인 대화상자 | 됨 |
| 폴링 안정화 | 재시도 직후 옛 응답이 덮어쓰는 문제, 404에 끝없이 폴링하는 문제 수정 | 됨 |
| 1.1~1.3 화면 | 업로드, 항별 진행, 원문 보기, 재생성 미리보기 | 됨 |
| 검수 기록 API | `GET /review`, `PUT /review/fields`, `PUT /review/sections` | 안 됨 |
| 2.1 방식 선택 | 입력 유형 판정, 항별 건수, 권장 카드 | 안 됨 |
| 2.2 추출값 확인 | 칸별 확인·수정·되돌리기, 항 확인 완료, 원문 줄 강조 | 안 됨 |
| API 명세 | 4.8~4.11절 추가 | 일부 |
| RunPod | 새 Pod에 vLLM 설치·기동, 실제 문서 1건 추출 성공 | 해당 없음 |

## 작업 중 내린 결정

아래 결정은 사용자 확인 없이 제가 정한 것이 포함되어 있어 검토가 필요합니다.

| 결정 | 이유 | 대가 |
| --- | --- | --- |
| 검수 기록을 서버의 `review.json`에 저장 | 브라우저를 바꿔도 남고 이력이 보존됨 | 파일 기반이라 동시 수정에 약할 수 있음 |
| 추출 결과 파일은 고치지 않음 | 모델 출력과 사람 수정을 구분 | `/result`에는 수정값이 나오지 않음 |
| 수정값은 재생성할 때만 덧씌움 | 원본을 한 곳에 유지 | 재생성에 쓰이지 않는 칸은 고쳐도 문서가 그대로 |
| 다시 시도하면 이전 기록을 `review.이전-<시각>.json`으로 옮김 | 새 결과에 옛 수정이 섞이지 않음 | 다시 검수해야 함 |
| 칸 단위와 항 단위 확인을 함께 둠 | 젯소 문서가 1,288칸이라 칸별 확인만으로는 어려움 | 항 확인이 곧 칸별 대조를 뜻하지는 않음 |
| 값이 있는 칸만 표시·수정 | 첫 구현 범위를 줄임 | 누락된 값을 추가할 수 없음 |
| 검토자 이름은 인증 없이 기록 | 로그인 기능이 없음 | 기록의 이름을 보증하지 못함 |
| 재생성 스크립트를 회사가 준 10-31 버전으로 교체 (작업 폴더만) | 옛 버전이 빈 문서에서 `KeyError` 발생 | 본 checkout에는 옛 버전이 남아 있음. 이 파일은 D-47로 커밋 불가 |

## 확인한 범위

백엔드 시험 2,660개가 통과했지만(18개 건너뜀), 2.1·2.2는 실제 8020 서버에서 아직 확인하지 못했습니다.

**확인함**

- 백엔드 시험: 오늘 다시 실행해 통과. `test_D_htodb_api.py`는 PostgreSQL이 필요해 제외
- 프론트 타입 검사: 통과
- 실제 기록을 복사한 임시 서버에서 2.1 표시, 칸 확인, 숫자 입력 오류, 수정, 원문 줄 강조, 항 확인 완료. 수정 뒤에도 `/result` 원본 유지

**확인하지 못함**

- 실제 8020 서버에서 2.1·2.2 동작 (`/review` 경로가 아직 없음)
- 고친 값이 재생성 문서에 나오는 것을 화면에서 확인 (API 시험만 함)
- 새로 고침 뒤 유지되는 것을 브라우저에서 끝까지 확인 (저장은 시험으로 확인)
- 복사본 확인 뒤 바꾼 묶음 제목의 화면 표시 (시험만 함)
- 실제 문서는 1건만 돌림. 스캔본이나 여러 문서에서는 확인하지 못함

백엔드 시험은 `backend/`에서 아래처럼 실행해야 합니다. `pytest`만 실행하면 `scripts` 모듈을 찾지 못합니다.
