# 정합성 결과 → 판정 화면(API-12·13) 변환 함수 사용 안내

작성 F 김우진 · 2026-11-03 · 대상: 백엔드(API-12·13 구현), 화면(E, e/frontend-review)

## 1. 무엇을 넘기나

판정 화면은 `frontend/src/api/findings-schemas.ts`(E, e/frontend-review)의 모양으로 데이터를 받는다. 정합성 엔진 결과(`run_consistency`, 설계서 44장)는 코드·한글 판정·구조화된 계산 근거라서 모양이 다르다. 그 사이를 `backend/src/msds/compliance/api_view.py`가 바꾼다.

- 화면 계약은 바꾸지 않는다. 엔진이 바뀌면 이 파일만 고친다.
- 백엔드는 변환 결과를 저장해 두고, 목록·상세 요청에 그대로 내보내면 된다.

## 2. 쓰는 법

```python
from msds.compliance.consistency import run_consistency
from msds.compliance.explain import ChatExplainer, explain_consistency
from msds.compliance.api_view import api_view, findings_response, finding_detail

views = []
for i, item in enumerate(doc["msds"]):                      # 추출 JSON 한 건 안의 MSDS마다
    res = run_consistency(doc, repo, i)                     # repo=None 이면 실제 HTODB, CsvRepo() 면 샘플 CSV
    explain_consistency(res, item, llm)                     # llm=None 이면 문장틀 설명만
    views.append(api_view(res, item, msds_id=msds_id, validation_id=validation_id,
                          page_path="pages/{page}.png"))    # 원문 쪽 이미지 경로 규칙

# API-12  GET .../validations/{validation_id}/findings?verdict=&section=
findings_response(views, validation_id=..., extraction_id=..., review_revision=0,
                  verdict="mismatch", section=15, page=1, page_size=20)

# API-13  GET .../findings/{finding_id}
detail = finding_detail(views, finding_id)                  # None 이면 404
```

`api_view()`는 MSDS 한 건의 결과를 `{"msds_id", "validation_id", "details": [...], "groups": {...}}`로 돌려준다. `details`의 원소가 API-13 상세 하나이고, 그 안의 `finding`이 API-12 목록 한 줄이다. JSON으로 그대로 저장할 수 있다.

## 3. 값 대응 (고정)

| 엔진 | 화면 |
|---|---|
| 일치 · 불일치 · 경계 · 근거부족 | match · mismatch · borderline · insufficient_evidence |
| 판정에서 뺀 줄: 15항 구버전 | outdated (목록에 보임) |
| 판정에서 뺀 줄: 15항 참고, 2항 대조·판단불가 | excluded (excluded_counts 에만) |
| 판정에서 뺀 줄: 2항 해당 없음(성상·운송 조건) | not_applicable (excluded_counts 에만) |
| 높음 · 중간 · 낮음 | high · medium · low |
| 설명 by llm · template / 검사 통과 | explanation.source ai · template / check_status passed · failed |
| 설명 없음(일치 줄) | source unavailable, check_status not_checked, text "" |
| 항목 코드 HH_ACUTE_INHAL | item "급성독성물질(흡입)" (rules/class_map.csv 이름) |
| 15항 법 코드 OSH, 항목 OSH_SPECIAL | law "산안법", item "특별관리물질" (rules/reg_map.csv) |
| MSDS 값 · 계산 값 | "구분 2 (증기)", "해당 (>= 0.1%)", "— (근거부족 사유)" 같은 글자 |
| 계산 근거(trace) | inputs · thresholds · assumptions 글자 줄. 차이 원인은 inputs 끝에 "차이 원인: …" |

- `warning`은 쓰지 않는다. 엔진은 표시 요소 '경고'도 불일치·낮음으로 낸다.
- 엔진 공통 가정(판정 줄 절반 이상에 똑같이 붙는 것)은 줄마다 보이지 않는다. 전체 목록은 `docs/2026-11-02_F_규칙표_가정목록.md`.

## 4. 번호 규칙

| 칸 | 규칙 | 예 |
|---|---|---|
| finding_id | `{msds_id}-{엔진 번호}` | `msds_a-F-2-005` |
| trace_id | `{msds_id}-{엔진 trace 번호}` | `msds_a-T-2-005` |
| 판정에서 뺀 줄 | `{msds_id}-X-{항}-{순번}` | `msds_a-X-15-001` |
| component_id | `{msds_id}-c{성분 seq}`, 제품 전체 줄은 null | `msds_a-c1` |
| groups(15항 성분 묶음) | 성분별 + 제품 전체는 `product` | `황산 (93~98%)`, `제품` |

계산 근거가 없는 줄(MSDS에만 있는 항목)도 `trace_id`는 문자열로 주고, 상세의 `trace`는 null이다.

## 5. 백엔드가 채울 것

변환 함수는 기본값만 넣는다.

- `review_state`(unreviewed), `opinion_count`(0), 상세의 `review`, 목록의 `review_revision`(0): 검토 처리 결과로 덮어쓴다.
- `page_path`: 원문 쪽 이미지 경로 규칙. 기본 `pages/{page}.png`(화면 데모와 같음).
- `law_effective_date`: 지금은 null. 지식DB 시행일을 붙이면 채운다.
- `reference_date`는 검증 기준일(as_of), `msds_revision_date`는 추출 JSON의 최종 개정일이다.
