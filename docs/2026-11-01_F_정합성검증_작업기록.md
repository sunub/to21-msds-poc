## 1. 변경 기록

### #1 (11/01) 2항 불일치 유형 이름을 설계서 7·18장에 맞춤

**무엇을 바꿨나**
- `backend/src/msds/compliance/mixture/verdict.py`
  - 틀린 경우 네 가지(MSDS가 더 약함, MSDS 미기재, MSDS가 더 강함, 우리는 분류안됨인데 MSDS 기재)는 안쪽 구분으로 그대로 둔다. 이유 문장과 rule_id(VRD-2~5)를 나눠 쓰기 위해서다.
  - 결과의 `type` 값은 새 표 `TYPE_NAME`을 거쳐 설계서 이름 두 가지로 낸다.

    | 경우 | 이전 이름 | 바뀐 이름 | 심각도(변화 없음) |
    |---|---|---|---|
    | MSDS가 더 약한 구분 | 과소분류 | 과소분류 | 높음 |
    | MSDS 미기재 | 누락 | **과소분류** | 높음 |
    | MSDS가 더 강한 구분 | 과대분류 | 과대분류 | 낮음 |
    | 우리는 분류안됨, MSDS는 기재 | 과기재 | **과대분류** | 낮음 |

  - 파일 머리 설명과 가정 문구에서 "규칙표·설계서에 정의 없음(기본안)"을 "설계서 7장·18장, 규칙표 v0.3 severity.yaml을 따름"으로 고쳤다. 가정으로 남는 것은 rule_id(VRD-1~7) 번호뿐이다.
- `backend/tests/test_E_verdict.py`
  - 기대 이름 다섯 곳을 같은 기준으로 고쳤다.
  - `test_불일치_4유형`은 안쪽 구분과 바깥 이름을 따로 확인하도록 바꿨다.

**왜 바꿨나**
1. 10/30 결정 5장이 "판정 이름과 심각도는 설계서 체계로 통일"이라고 정했다.
2. 설계서 18장(단일물질 2항 비교 규칙)이 두 경우를 이렇게 정의한다.
   - "MSDS 미기재 또는 낮은 구분 → 불일치·과소(높음)"
   - "MSDS가 더 높은 구분·추가 → 불일치·과대(낮음)"
3. 설계서 7장과 규칙표 v0.3 `severity.yaml`에서 '누락'(규제 누락, SV-02)과 '과기재'(SV-08)는 **15항** 유형이다. 2항에 쓰면 15항 결과와 섞인다.
4. 설계서 48장 오류 주입 기대값이 "25번 2항에서 피부 부식성 삭제 → 과소분류(높음)"이다. 이전 이름이면 같은 상황이 '누락'으로 나와 기대값과 어긋난다.
5. 인계 문서와 이전 코드 주석은 "정의가 없어 가정으로 썼다"고 했지만, 위 근거로 정의가 있음을 확인했다.

**결과에 미친 영향**
- `type` 값만 바뀐다. 판정(일치·불일치·경계·근거부족), 심각도, rule_id, 이유 문장은 그대로다.
- 25번 황산
  - 흡입[분진·미스트]: 누락·높음 → **과소분류·높음**
  - 수생 만성, 표적장기(1회): 과기재·낮음 → **과대분류·낮음**
  - 합계는 같다(일치 21, 불일치 3, 근거부족 2).

**확인**
- `python -m pytest -q tests/test_E_verdict.py` → 17 passed (Windows, `HTODB_SKIP=1`)
- `local/run25.py` 재실행으로 위 변화를 확인했다.

**남은 점**

### #2 (11/01) 형태 불일치: 흡입 형태만 다른 두 줄을 한 줄로 묶음

**무엇을 바꿨나**
- `backend/src/msds/compliance/mixture/verdict.py`
  - 틀림의 경우에 '형태'를 더했다.
    - 결과 이름은 **형태·세부 표기**, 심각도는 **중간**, rule_id는 **VRD-8**이다.
  - 새 함수 `_merge_form_pairs`를 넣었다. 판정을 다 만든 뒤 같은 항목의 두 줄을 찾아 한 줄로 바꾼다.
    - 우리 쪽 줄: 우리는 형태 B에서 구분을 확정했는데 MSDS에는 B가 없음
    - MSDS 쪽 줄: MSDS는 다른 형태 A로 적었는데 우리 A 결과가 근거부족이거나 분류안됨
  - 묶은 결과는 이렇게 낸다.
    - 구분이 같으면 형태·세부 표기(중간)
    - 구분도 다르면 구분 방향에 따라 과소분류(높음) 또는 과대분류(낮음). 이유 문장에 "형태도 다름"을 적는다.
  - 모든 판정 줄에 `msds_form`(MSDS가 적은 형태)을 더했다. 보통은 `form`과 같고, 묶은 줄에서만 다르다.
    - 설계서 44장 결과 구조는 MSDS 형태와 우리 형태를 따로 두는데, 그 모양에 맞추기 위해서다.
    - 화면에서 "우리 분진·미스트 / MSDS 증기"를 함께 보여 줄 수 있다.
  - 묶지 않는 경우: 우리 결과가 범위(하한 ≠ 상한)일 때, 위험 순서를 모를 때. 두 줄을 그대로 둔다.
- `backend/tests/test_F_form_mismatch.py` (새 파일, 시험 8개)
  - 기본 사례, MSDS가 우리에게 없는 형태(가스)로 적은 경우, 구분도 다른 경우(과소·과대)
  - 묶지 말아야 하는 경우(MSDS가 같은 형태로 맞게 적음, 우리 결과가 범위), 같은 입력 같은 결과, 25번 황산
- `backend/tests/test_E_verdict.py`
  - 결과 필드 목록에 `msds_form`을 더했다.
  - 25번 시험의 기대값을 "증기 줄 근거부족"에서 "분진·미스트 줄 형태·세부 표기"로 바꿨다. 증기 줄은 묶여서 없어진다.

**왜 바꿨나**
1. 설계서 18장 비교 규칙: "흡입 형태(가스·증기·미스트) 다름 → 불일치·형태(중간)"
2. 설계서 24장 예제 2: 25번 황산은 우리 분진·미스트 2, MSDS 증기 2 → "불일치·형태(중간)"
   - 설계서 13·44장의 결과 예시도 같은 사례를 `type: 형태 표기, severity: 중간`으로 보여 준다.
3. 규칙표 v0.3 `severity.yaml` SV-03 "형태·세부 표기, 2항, 중간"
4. 묶기 전에는 한 가지 사실이 두 줄로 나왔다.
   - "MSDS가 흡입 위험을 빠뜨렸다(과소분류·높음)" + "증기 근거부족"
   - 위험의 크기(구분 2)는 MSDS가 맞게 적었으므로 높음 경보는 과하다.
5. 인계 6번 작업(완료 기준: 25번이 형태 불일치 한 줄로 나옴, 같은 입력 2회 동일, 기존 시험 통과)

**가정으로 둔 것** (결과의 assumptions에 `FORM_ASSUMPTION`으로 붙음)
- 구분도 다를 때의 처리는 설계서에 없다. 더 중요한 구분 차이(과소·과대)를 유형으로 쓰고, 형태 차이는 이유에 적었다.
- MSDS가 형태 없이 "흡입"만 적은 경우도 같은 방식으로 묶는다(이유에 '형태 미기재'로 표시).

**결과에 미친 영향**
- 25번 황산 흡입: 두 줄(과소분류·높음, 근거부족) → 한 줄
  - 불일치 · 형태·세부 표기 · 중간 · "구분은 같고 형태만 다름: MSDS는 증기 2, 우리는 분진·미스트 2"
- 합계: 일치 21, 불일치 3, 근거부족 2 → **일치 21, 불일치 3, 근거부족 1**

**확인**
- `python -m pytest -q tests/test_E_verdict.py tests/test_F_form_mismatch.py` → 25 passed
- `local/run25.py` 재실행

**남은 점**
- 인계 8번 ② KR02 '흡입:가스' 재분류(D-22)는 정부 DB 분류 쪽 문제다. 정부 DB 연결 작업 때 함께 본다.
