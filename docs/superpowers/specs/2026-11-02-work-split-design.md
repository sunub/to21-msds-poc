# 작업 나누기: A 2명 · B 2명 병렬 진행

작성 2026-11-02 · 상태: 승인 전 · 설계: 개요 `2026-11-02-backend-pipeline-design.md`, A `…-part-a-extraction-design.md`, B `…-part-b-judgment-save-design.md`

## 1. 원칙
- 네 사람이 첫날부터 동시에 시작한다. 그러려면 **사람 사이의 경계마다 약속(입출력 모양 + 견본 파일)을 먼저 고정**하고, 각자는 상대 대신 가짜(견본을 돌려주는 대역)를 끼워 개발한다.
- 경계는 함수 하나 또는 표 하나로 좁힌다. 상대 코드 안을 알 필요가 없게 한다.
- 파일과 DB 표에는 주인이 한 명씩 있다 (4절). 남의 파일을 고쳐야 하면 주인에게 요청한다.

## 2. 나누기

```
           A1 작업 흐름 담당              A2 결과·검수 담당              B2 판정 서비스 담당            B1 판정 엔진 담당
 업로드 ─▶ 대기열·작업자·재시작 ─▶ [약속 ②] 단계 함수 ─▶ 검증·재추출·넘김 ─▶ [약속 ①] 넘김 기록 ─▶ 판정 버전·설명·저장 ─▶ [약속 ③] judge() ─▶ 2·15항 판정
            모델 호출 창구 ◀──────────── [약속 ④] 창구 사용법 ─────────── (A2 재추출, B2 설명도 사용)
```

### A1 — 작업 흐름 (추출을 "돌리는" 쪽)
- `extract` 스키마의 대기열·작업 상태 표, `SKIP LOCKED` 가져가기, 서버 재시작 복구(`interrupted`), 자동 재시도 1회, `/retry`.
- 전처리 줄과 추출 줄 분리, 동시 추출 수 N을 설정으로.
- **모델 호출 창구**(공용 모듈) 구현: 서버 전체 동시 호출 상한, 추출 우선 순서.
- **동시 추출 실험**(A 설계 4절)과 ADR.
- 대기 순번·예상 시간 계산과 목록·상세 API의 그 칸.
- 가짜로 돌리는 것: 단계 함수(약속 ②)를 잠깐 자는 가짜로 끼워 대기열·복구를 시험한다. 지금 `service/pipeline.py`의 `Steps`가 이미 가짜를 끼울 수 있다.

### A2 — 결과·검수·넘김 (추출 "결과"를 다루는 쪽)
- 단계 함수 본체: 전처리 → 항목 분할 → 추출 → **검증·오류 항 1회 재추출** → 넘김①. (전처리·분할·추출 코드 자체는 지금 것을 쓰고, 묶는 일을 한다.)
- `extract` 스키마의 추출 결과·검수 기록 표, `state.json`·`review.json` 옮기기.
- 같은 파일 재사용(설정 키), 이전 실행 검수 기록 보존.
- 넘김 기록 만들기(넘김①·②), "판정으로 넘기기" API, 검수 API, 재생성(TO21 `DB적재_재생성_v0.6`).
- 가짜로 돌리는 것: 대기열 없이 단계 함수를 직접 부르며 개발한다. 모델 창구는 약속 ④의 가짜(동시 제한만 하는 세마포어).

### B1 — 판정 엔진 (상태 없는 순수 계산)
- `judge(extraction, as_of, provider) → consistency 블록`(약속 ③) 하나를 만든다. DB에 쓰지 않는다.
- 지식 제공자: HTODB 조회(`compliance/htodb`), 설계서 v0.4 15장 3개 함수, `ghsclass` 끼움 자리 두 개.
- 규칙표 v0.3, ① 입력 정리 ~ ⑥ 판정 집계, trace, 차이 원인 코드.
- 설계서 v0.4 48장 개발 순서 1~7단계와 49장 단위·적합성·e2e 테스트 (설명 생성인 8단계는 B2).
- 가짜로 돌리는 것: 없음. 입력은 25번 황산 정답 예제와 Msds-test_v0.4 데이터.

### B2 — 판정 서비스 (판정을 "언제·어떻게 쌓고 보이는지")
- `judge` 스키마: 넘김 기록 가져가기, 판정 키(재계산 안 함), 판정 버전, 버전 간 차이.
- 설명 생성: 요청 만들기, 숫자 환각 검사, 템플릿 대체, 바뀐 항목만 다시 생성. 모델 창구 뒤쪽 순서.
- 판정 검토 이벤트(finding ID 고정), 저장본, B API, 리포트 내려받기.
- 가짜로 돌리는 것: `judge()`는 약속 ③ 견본(25번 consistency 블록)을 돌려주는 가짜. 넘김 기록은 약속 ① 견본을 시험용 API로 직접 넣는다. 모델 창구는 약속 ④의 가짜.

## 3. 첫날 함께 고정할 약속 (시작 전, 네 명 같이)

각 약속은 **모양(JSON Schema 또는 파이썬 시그니처) + 견본 파일 + 견본으로 통과하는 계약 시험**까지 만들어 저장소에 넣는다. 둘 다 이 시험을 돌린다.

| 약속 | 사이 | 고정할 것 | 견본 |
|---|---|---|---|
| ① 넘김 기록 | A2 → B2 | 개요 6.1의 칸, `extract.handoff` 표 정의, B 읽기 권한 | 25번 황산 정답 예제로 만든 넘김 기록 1건, 같은 작업의 `handoff_seq` 2건(값 하나 수정) |
| ② 단계 함수 | A1 → A2 | `process(job_id, ctx) -> None`, 진행 이벤트 종류(`service/progress.py`의 이벤트 + `checks`), 실패는 예외 대신 `failed` 이벤트 | 가짜 단계 함수 (몇 초 자고 이벤트만 냄) |
| ③ 판정 함수 | B2 → B1 | `judge(extraction, as_of, provider) -> dict`, 결과는 설계서 v0.4 45장 consistency 블록에서 `review` 뺀 것, finding ID 규칙(2항 `class_code`+`route_form`, 15항 성분×`law`×`item_code`), 버전 칸 | 25번 황산 consistency 블록 (손으로 만든 고정본, B1 e2e 고정본이 나오면 교체) |
| ④ 모델 창구 | A1 → A2·B2 | `async with gate.slot(kind="extract"|"explain"): …` 모양, 상한 설정 이름 | 세마포어만 하는 가짜 창구 |
| ⑤ 화면 API | A2·B2 → 화면 | 새로 생기는 경로(대기 순번, 판정으로 넘기기, 판정 보기·버전·검토·저장)의 응답 모양 | 각 경로 응답 견본 JSON (`frontend/src/api/schemas.ts`와 맞춤) |

약속을 바꿔야 하면 양쪽이 같이 바꾸고 견본과 계약 시험을 함께 고친다.

**스키마 초안**: `contracts/` 폴더 (추출 데이터는 TO21 추출스키마 v0.6 기준). 0일차에는 이 초안을 함께 읽고 고쳐 확정한다. 견본은 저장소에 JSON으로 올리지 않고 시험 픽스처가 `to21_file()`로 만든다 (D-47, `contracts/README.md` 4절).

## 4. 주인 (겹침 방지)

| 주인 | 파일·표 |
|---|---|
| A1 | `service/worker.py`(대기열 작업자로 교체), `service/store.py`의 작업 상태 부분 → 새 `service/jobs.py`, 공용 모델 창구(새 `common/model_gate.py`), `extract_app.py`의 업로드·목록·상세·재시도 경로, `extract.jobs` 표, 실험 스크립트·ADR |
| A2 | `service/pipeline.py`, `service/review.py`, `service/regenerated.py`, `service/progress.py`, `checks/`, `extract_app.py`의 결과·검수·재생성·넘기기 경로, `extract.results`·`extract.reviews`·`extract.handoff` 표 |
| B1 | `compliance/` 전체(새 엔진·제공자·규칙표), `compliance/rules/` |
| B2 | 새 `judge/`(서비스·작업자·설명·저장), 새 `api/judge_app.py`(B 라우터), `judge` 스키마 표 전부 |

- `extract_app.py`는 A1과 A2가 같이 쓰므로 첫 작업으로 A1이 경로를 두 파일(작업·검수)로 나눈다.
- DB 마이그레이션 파일은 사람별 접두어(`a1_`, `a2_`, `b2_`)와 번호로 이름을 지어 충돌을 막는다. B1은 DB에 쓰지 않는다.
- `extract/`(프롬프트·클라이언트·section_runner)는 이번 작업에서 고치지 않는다. 창구를 끼우는 한 줄(`extract/client.py`)만 A1이 고친다.

## 5. 순서와 합치는 때

```
0일차     네 명: 약속 ①~⑤ 고정, 견본·계약 시험 커밋, extract_app.py 나누기(A1)
1주차     A1 대기열·창구 / A2 단계 함수·넘김 / B1 입력 정리·판별·지식 제공자 / B2 판정 버전·검토·저장 (모두 가짜 상대로)
          ── 합치기 1: A1+A2 (진짜 단계 함수로 대기열 돌리기) · B2+B1 (진짜 judge로 25번)
2주차     A1 동시 추출 실험·ADR / A2 재사용·재생성 / B1 혼합물·15항·공통 검증 / B2 설명 생성
          ── 합치기 2: A ↔ B (넘김 기록 표로 이어 업로드 → 저장까지)
마무리    20건 부하 시험, 재시작 시험, 같은 입력 2회 시험, 화면 연결
```

- 합치기 전에는 각자 계약 시험과 자기 시험만 통과하면 된다.
- 합칠 때 문제가 나오면 먼저 견본과 실제 값의 차이를 본다. 약속이 틀렸으면 약속부터 고친다.

## 6. 나누기에서 남는 위험
- **B1이 가장 길다.** 설계서 v0.4 개발 순서 1~7단계 전부다. B1이 늦으면 B2는 가짜 `judge()`로 끝까지 가고, 합치기 2에서는 B1이 끝낸 단계까지만 진짜로 붙인다 (설계서도 "1~4단계만 끝나도 단일물질과 15항 검증은 동작"). 설명 생성은 B2가 맡아 B1의 짐을 덜었다.
- **A1의 실험 결과가 A 전체 속도를 정한다.** 실험은 2주차 초에 해서, N=1로 나오면 그때 예상 시간을 공유한다.
- **약속 ③ 견본은 처음에 손으로 만든다.** B1의 실제 출력과 다를 수 있으니, B1 e2e 고정본이 나오는 대로 견본을 교체하고 B2가 다시 계약 시험을 돌린다.
