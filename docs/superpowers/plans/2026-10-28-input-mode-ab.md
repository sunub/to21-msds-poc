# 입력 비교 실험: '이미지만' 대 '이미지+글자' (계획, 2026-10-28)

## 묻는 것

쪽 이미지에 텍스트(텍스트층 또는 OCR 글)를 함께 넣으면 추출 점수가 오르는가. 오른다면 어느 칸에서인가.
답에 따라 행 묶기·OCR 보정에 더 시간을 쓸지 정한다.

개발 문서로만 돌린다 (D-43). 평가 문서는 쓰지 않는다.

- **S003**: 비교가 안 된다. 다음 중 하나를 고른다 (미정).
  - (가) S003을 빼고 텍스트층이 정상인 개발 문서로 바꾼다. 후보: **S014** (7쪽, 가장 짧음)
  - (나) S003에 '이미지+OCR 글' 조건을 새로 만든다. 지금은 글꼴깨짐 쪽에 글을 넣지 않는다. 넣을지는 F와 정하기로 한 일이라(`ocr.py` 머리말), 이 실험만으로 정하지 않는다
  - (다) S003을 같은 입력으로 두 번 돌려 **실행마다 생기는 흔들림**을 재는 대조군으로 쓴다

## 조건과 모델

| 조건 | 정상 쪽에 넣는 것 |
|---|---|
| A. 이미지만 | 쪽 이미지 + 표시 "[글자 없이 이미지만 보고 읽으세요]" |
| B. 이미지+글자 | 쪽 이미지 + 텍스트층 또는 OCR 글 (지금 방식) |

A 조건의 표시 문구는 지금 깨진 쪽에 쓰는 "[텍스트층 없음 또는 깨짐 …]"을 쓰지 않는다. '깨짐'이라는 말이 모델이 글자를 덜 믿게 만들 수 있어서다.

모델 (미정):
- **기준선 Qwen3.8-27B**: 꼭 돌린다. 최종 결과를 내는 모델이고, 작은 모델이라 글자 보조 효과가 클 수 있다. temperature 0이라 한 번만 돌린다.
- 상용 모델 하나 (Claude 또는 GPT): 실버 초안의 입력 방식을 정하는 데 필요하면 돌린다. 출력이 실행마다 달라질 수 있어 조건마다 두 번씩 돌려 흔들림을 본다.

## 정답

두 조건 중 어느 쪽 결과로 초안을 만들어도 그쪽에 유리한 정답이 된다. 그래서 다음처럼 한다.

- 아래 '점수 낼 칸'만 사람이 원문과 대조해 정한다 (골드, `data/gold/`). 문서 하나에 칸 전체를 다 채우지 않는다.
- 초안은 두 조건의 결과가 아니라 **텍스트층/OCR 글을 직접 보고** 만든다. 검수하는 사람은 어느 조건의 값인지 모르는 상태로 본다.
- 검수하지 못한 칸은 "미검수"로 표시하고, 그 점수는 "참고"로 따로 보고한다.

## 점수 낼 칸

TO21 채점기 v0.5의 항목 가운데, 글자를 정확히 읽어야 하는 칸을 **주 지표**로 둔다. 이미지로만 알 수 있는 칸은 **대조군**으로 둔다. 대조군 점수가 조건에 따라 달라지면, 그 차이는 입력이 아니라 실행마다 생기는 흔들림이다.

| 구분 | 채점기 항목 | 지표 | 글자가 돕는다고 보는 이유 |
|---|---|---|---|
| 주 | 관리정보(제출번호·작성일·개정일·개정횟수) | 정확도 | 긴 번호, 날짜 |
| 주 | 제품명·회사명·긴급연락처 | 정확도 | 전화번호, 영문 제품명 |
| 주 | 구성성분(CAS 기준 매칭) | F1 | CAS 번호 숫자 |
| 주 | 구성성분 필드(성분명·KE) | 정확도 | 긴 화학명, KE 번호 |
| 주 | 함유량(부등호·값·단위 6요소) | 정확도 | `~`, `<`, `%` 같은 기호. OCR 사전에 `~`가 없다 |
| 주 | 8항 노출기준(성분·출처·종류·값) | F1 | 작은 숫자 |
| 주 | 9항 필수 물성(특성·값) | F1 | `℃`, 소수점. OCR 사전에 `℃`가 없다 |
| 주 | 11항 급성독성(경구·경피·흡입) | F1 | LD50 값과 단위 |
| 주 | 14항 운송(UN번호·등급·용기등급) | 정확도 | UN 번호 |
| 주 | H 코드 / P 코드 | F1 | 코드 목록이 길다 |
| 대조군 | 그림문자 | F1 | 그림이라 글자가 돕지 않는다 |
| 대조군 | 신호어 | 정확도 | 크게 쓰인 한 단어 |
| 참고 | 서술형 문장(문자 유사도) | 유사도 | 긴 문장을 베끼는 데 글자가 크게 도울 것으로 본다. 정답이 길어 이번엔 골드를 만들지 않는다 |

나머지 항목(유해성 분류, 15항 규제, CMR, 생태 등)은 채점기가 내는 대로 함께 적되 결론에 쓰지 않는다.

평균만 보지 않는다. 문서 두세 건이라 평균 차이는 우연일 수 있다. **칸마다 두 조건 중 어느 쪽이 맞혔는지**를 표로 만들고, 틀린 값은 원인을 붙인다 (글자 오독 / 칸 섞임 / 빠뜨림 / 지어냄).

함께 적는 것 (`log.jsonl`): 입력·출력 토큰, 걸린 시간, 출력 잘림(`finish_reason`), 스키마 재시도 횟수.

원문 대조 일치율은 비교 지표로 쓰지 않는다. B 조건은 모델이 글자를 보고 베끼므로 일치율이 저절로 높게 나온다.

## 순서

1. **코드 수정** (작게)
   - `run_baseline.py`, `run_silver.py`에 `--input-mode {이미지만,이미지+글자}`를 추가한다. 주면 manifest 값을 덮어쓴다
   - `extract_document`에 `input_mode` 인자를 추가하고 `run_info.yaml`에 기록한다
   - A 조건 표시 문구를 바꾼다 (위)
   - 시험: `page_parts`가 조건마다 텍스트를 넣고 빼는지 확인한다
2. **프롬프트 만들기:** `python scripts/build_prompts.py`. 두 조건 모두 `p1`.
3. **파일럿:** S016, 묶음 b1만, 조건 A·B, Qwen. 호출 2번. 실제 토큰과 시간을 보고 위 비용을 다시 계산해 공유한다. **이 단계에서 멈추고 확인을 받는다.**
4. **본 실행:** 실행 이름 `<날짜>_inputab_<모델>_<img|imgtxt>`. 문서 × 묶음 5개 × 조건 2개.
5. **정답 만들기:** 위 '점수 낼 칸'만 사람이 검수해 골드로 만든다. 조건을 모르는 상태에서 본다.
6. **채점과 정리:** TO21 채점기 v0.5로 채점하고, 칸별로 어느 쪽이 맞혔는지 표를 만든다. 결과는 `runs/<날짜>_inputab_report/`에 둔다.

## 결론 내는 기준 (미리 정해 둔다)

- **B를 쓴다:** 주 지표에서 B만 맞힌 칸이 A만 맞힌 칸보다 확실히 많고, 대조군에는 차이가 없다.
- **A로 충분하다:** 두 조건이 맞힌 칸이 거의 같다. 그러면 행 묶기·OCR 보정은 모델 입력용으로는 우선순위를 낮추고, 원문 대조용으로만 손본다.
- **판단 보류:** 대조군도 흔들린다. 반복 실행을 늘리거나 문서를 더한다.
