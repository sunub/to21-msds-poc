# version8 / version9가 같은 .py 파일인 이유

`backend/scripts/ocr_batch_version8.py` **하나**가 version8과 version9 결과물을 둘 다 만든다. 파일을 두 개 만든 게 아니라, `--output-version` 옵션으로 출력 폴더 이름만 바꿔서 재사용한 것.

## 코드

```python
def main() -> int:
    parser = argparse.ArgumentParser(description="version8: pipe-row OCR 전체 실행")
    parser.add_argument("--doc-id", help="한 문서만 실행")
    parser.add_argument("--force", action="store_true", help="기존 결과도 새로 실행")
    parser.add_argument("--output-version", default="version8", help="출력 폴더 이름 (예: version9)")
    args = parser.parse_args()
    return run_extractor(
        output_version=args.output_version,
        pipe_rows=True,
        line_numbers=True,
        force=args.force,
        selected_doc_id=args.doc_id,
    )
```

`output_version`을 안 주면 기본값 `"version8"`로 `data/pages/version8/`에 쓰고, `--output-version version9`를 주면 똑같은 코드가 `data/pages/version9/`에 쓴다.

## 실제로 돌린 명령

| 실행 | 명령 | 결과 |
|---|---|---|
| version8 | `python ocr_batch_version8.py --doc-id T21-025 --force` 등 (일부 문서만) | `data/pages/version8/` — T21-025, S003, S013, S016, M013 등 테스트용 일부 문서 |
| version9 | `python ocr_batch_version8.py --output-version version9 --force` (manifest 전체) | `data/pages/version9/` — 20개 문서 전체 |

## 왜 같은 코드로 처리했나

- **방법이 완전히 동일함**: 둘 다 `ocr_batch_version2.main()`을 `pipe_rows=True`, `line_numbers=True`로 고정 호출한 것. 로직에 차이가 없는데 스크립트를 복제하면 코드 중복만 생김.
- **차이는 "대상 문서 범위"뿐**: version8은 표 묶기 수정이 제대로 됐는지 **먼저 T21-025 1건으로 테스트**한 것이고, version9는 그 방법이 맞다고 확인된 뒤 **manifest 20개 문서 전체로 확장 실행**한 것. 즉 version8 → version9는 "같은 방법의 테스트 실행 → 전체 실행" 관계.

## 혼동 포인트

- 스크립트 **파일 이름**은 `ocr_batch_version8.py`로 고정돼 있는데, 실제로 만들어지는 **출력 폴더 이름**은 `--output-version` 인자로 달라진다. "왜 버전 9인데 8을 실행하냐"는 질문이 여기서 나왔던 것.
- 참고로 커밋 히스토리도 같은 파일 하나가 두 번 수정된 것으로 남아있다:
  - `77ec03b`: `ocr_batch_version8.py` 최초 작성 (pipe_rows만 켬)
  - `cea7208`: 같은 파일에 `line_numbers=True` 추가 + `--output-version` 인자 추가 → version9 실행에 사용

## 참고

스크립트 이름을 `ocr_batch_pipe_lines.py` 같은 버전 중립적인 이름으로 바꾸면 이 혼동이 줄어들 수 있음(아직 미반영, 제안 상태).
