# 추출 서비스 API 명세 (2026-11-01)

PDF 한 건을 올리면 전처리 → 항목 나누기 → 항별 모델 추출 → 정리·검증을 서버가 뒤에서 처리하고,
화면은 진행 상태를 주기적으로 물어 보여 준다. 이 문서는 그 API의 요청·응답 모양과 동작을 정리한다.

- 서버 코드: `backend/src/msds/api/extract_app.py` (FastAPI)
- 처리 흐름·상태: `backend/src/msds/service/` (`pipeline.py`, `progress.py`, `store.py`, `worker.py`)
- 프론트엔드 계약: `frontend/src/api/schemas.ts` (zod). 이 문서와 같은 모양이다. 어긋나면 서버 코드가 기준이다.
- 시험: `backend/tests/test_E_service.py`, `test_E_extract_app.py`, `test_E_preprocess_progress.py`

cd backend

# 자동 생성 문서: http://localhost:8020/docs

## 2. 처리 흐름

```
POST /api/documents ──► 대기열 ──► 작업자(한 번에 한 건)
                                    │
  1 전처리       render.preprocess          쪽 이미지·쪽 글 → data/pages/<번호>/      (쪽마다 진행)
  2 항목 나누기   pipeline.write_sections    16개 항 경계 → data/service/sections/<번호>.json (경계는 16개 모두 필요)
  3 모델 추출     section_runner.run_document  (MSDS 건 × 추출 대상 9개 항)을 동시에 호출       (항마다 진행)
  4 정리·검증     run_document 안의 펼치기·검사 → data/service/runs/<번호>/
```

- **진행의 기본 단위는 항목(MSDS 건 × 추출 대상 9개 항)이다.** 추출 대상은 1·2·3·8·9·11·12·14·15항뿐이다(기업 합의 2026-10-29, 기술명세 2.9). 나머지 항은 모델을 부르지 않으며 골드에서도 비어 있다. 추출은 항별로 동시에(기본 16개까지) 돌기 때문에
  쪽이 하나씩 차례로 끝나지 않는다. 항이 걸친 쪽(`pages`)은 원문 이동용으로만 같이 준다.
- 문서끼리는 차례로 처리한다. 한 건 안에서 이미 여러 항을 동시에 부르기 때문이다.
- 어느 단계에서 실패해도 서버는 멈추지 않는다. 그 문서를 `failed`로 남기고 다음 문서로 간다.
- 한 항의 모델 호출이 실패하면 그 항만 `failed`가 되고 나머지 항은 계속한다. 이 경우 문서는 `done`으로 끝나며,
  실패한 항은 결과에서 빈 값이고 `needs_review`로 표시된다.
- 진행 상태는 바뀔 때마다 파일에 쓴다. 화면을 닫거나 서버를 다시 켜도 이어서 볼 수 있다.
- 서버를 다시 켜면 돌던(`running`) 문서는 `interrupted`가 되고, 대기 중(`queued`)이던 문서는 다시 대기열에 들어간다.

### 저장 위치 (모두 git에 올리지 않는다)

| 위치 | 내용 |
|---|---|
| `data/service/<번호>/source.pdf` | 올린 원본 |
| `data/service/<번호>/state.json` | 진행 상태 |
| `data/pages/<번호>/` | 쪽 이미지(`pNNN.png`), 쪽 글(`pNNN.txt`), `meta.json` |
| `data/service/sections/<번호>.json` | 항목 경계. 제목을 하나도 못 찾으면 만들지 않고, 추출기가 임시 분할로 간다 |
| `data/service/runs/<번호>/` | `outputs/`(TO21 JSON), `checks/`, `raw/`(항별 모델 응답), `timing.jsonl`, `run_info.yaml` |

`raw/`는 그 항이 끝나는 즉시 쓴다. 서버가 도중에 꺼져도 끝난 항의 값은 남는다. 나머지는 문서가 끝날 때 쓴다.

문서 번호는 `U-<날짜>-<순번>`이다(예: `U-20261101-001`). manifest의 `T21-` 번호와 겹치지 않는다.

## 3. 상태 값

### 문서 상태 `status`

| 값 | 뜻 | 폴링 |
|---|---|---|
| `queued` | 대기열에 있음 | 계속 |
| `running` | 처리 중 (`stage`가 어느 단계인지 알려 준다) | 계속 |
| `done` | 끝남. 결과를 볼 수 있다 | 멈춤 |
| `failed` | 단계 하나가 실패함. `error`에 사유가 있다 | 멈춤 |
| `interrupted` | 처리 중에 서버가 꺼짐 | 멈춤 |

`failed`와 `interrupted`, 실패한 항이 있는 `done`은 `POST /retry`로 처음부터 다시 돌릴 수 있다. 응답의 `can_retry`가 알려 준다.

### 작업 단계 `stage`, `stage_index`

| `stage` | `stage_index` | 화면 문구 예 |
|---|---|---|
| `null` | 0 | 대기 중 |
| `preprocess` | 1 | 쪽 이미지와 글자를 만드는 중 |
| `sections` | 2 | 항목을 나누는 중 |
| `extract` | 3 | 항목별로 추출하는 중 |
| `finalize` | 4 | 결과를 정리하고 검사하는 중 |
| `done` | 4 | 끝남 |

`stage_total`은 늘 4다. 화면의 "1 / 4단계"는 `stage_index / stage_total`이다.
실패한 문서는 실패한 단계의 `stage`가 그대로 남는다. 항의 `status`도 멈춘 그대로 남으므로(`running` 포함), 문서가 끝난 상태면 화면은 그 항을 "멈춤"으로 보여 준다.

### 항 상태 `sections[].status`

| 값 | 뜻 |
|---|---|
| `queued` | 아직 호출 전 |
| `running` | 모델 호출 중 (재추출 포함) |
| `done` | 받은 응답이 형식 검증을 통과함 |
| `failed` | 호출이나 형식 검증이 끝내 실패함 |

`needs_review`(참·거짓)는 상태와 따로 온다. **성공(`done`)했지만 사람이 봐야 하는 항이 있기 때문이다.**
실패한 항이거나, 원문에 없는 줄 번호·통째로 빈 코드표 칸 같은 검사 문제가 남은 항이면 참이다.

### 4.1 `GET /api/health`

```json
{ "ok": true, "model_tag": "qwen36_35b_runpod" }
```

### 4.2 `POST /api/documents` — PDF 올리기

본문은 **PDF 바이트 그대로** 보낸다. multipart가 아니다. 폐쇄망 반입 목록에 의존성(python-multipart)을 늘리지 않기 위해서다.

| 쿼리 | 필수 | 형식 |
|---|---|---|
| `filename` | 예 | 1~255자, `.pdf`로 끝남. 경로가 붙어 있으면 파일 이름만 남긴다 |
| `as_of` | 아니오 | `YYYY-MM-DD` 기준일 |

```http
POST /api/documents?filename=젯소.pdf&as_of=2026-10-31
Content-Type: application/pdf

%PDF-1.7 ...
```

```ts
// 프론트엔드: frontend/src/api/documents.ts
createDocument(file, { filename: file.name, as_of: "2026-10-31" });
```

- **202**: 대기(`queued`) 상태의 [문서 진행 상태](#52-문서-진행-상태-상세)를 돌려준다. 바로 대기열에 들어간다.
- 같은 내용(sha256)의 PDF를 먼저 올린 적이 있으면 `duplicate_of`에 그 문서 번호들이 온다. 막지는 않는다.

| 오류 | 경우 |
|---|---|
| 400 | `.pdf`가 아닌 파일 이름, 본문이 `%PDF-`로 시작하지 않음 |
| 413 | 50MB 초과 |
| 422 | `filename`이 비었음, `as_of` 형식이 틀림 |

### 4.3 `GET /api/documents?status=` — 목록

| `status` | 고르는 문서 |
|---|---|
| `all` (기본) | 전부 |
| `active` | `queued`, `running` |
| `done` | `done` |
| `failed` | `failed`, `interrupted` |

```json
{
  "items": [ /* 문서 한 줄 (5.1), 새로 올린 것부터 */ ],
  "counts": { "all": 3, "active": 1, "done": 1, "failed": 1 }
}
```

`counts`는 필터와 상관없이 늘 전체 기준이다(보기 전환 알약에 쓴다).

### 4.4 `GET /api/documents/{id}` — 진행 상태 (폴링)

[문서 진행 상태](#52-문서-진행-상태-상세)를 돌려준다. 머리글과 1.2·1.3 진행 화면이 같은 응답을 쓴다. 없는 문서면 404.

**폴링 규칙**: 2초마다 부르고 `status`가 `done`·`failed`·`interrupted`가 되면 멈춘다.
`documentDetailQuery(id)`(TanStack Query)가 이렇게 설정되어 있다. 응답이 작아 부담이 없다
(문서 한 건에 항 9~18개).

### 4.5 `GET /api/documents/{id}/pages/{n}/image`

`n`은 1부터. 쪽 이미지(150dpi PNG). 전처리가 그 쪽을 만들기 전이면 404이므로, 화면은 `<img onError>`로 자리 표시를 보여 준다.
주소는 `pageImageUrl(id, n)`으로 만든다.

### 4.6 `GET /api/documents/{id}/pages/{n}/lines`

줄 번호가 붙은 쪽 글. 줄 번호(`p1:L3`)는 **모델이 근거로 적는 줄 번호와 같다.** 검수 화면에서 근거 줄을 강조할 때 그대로 쓴다.

```json
{
  "page": 1,
  "lines": [
    { "id": "p1:L1", "no": 1, "text": "물질안전보건자료 (MSDS)" },
    { "id": "p1:L3", "no": 3, "text": "1. 화학 제품과 제조회사 정보" }
  ]
}
```

빈 줄은 세지 않는다. 쪽 글이 아직 없거나 없는 쪽이면 404, `n < 1`이면 422.

### 4.6.1 `GET /api/documents/{id}/pages/{n}/boxes`

OCR로 읽은 쪽(글꼴이 깨졌거나 스캔한 PDF)의 글과 자리. 이런 쪽은 원본 PDF 글자 층으로 근거를 찾을 수 없어 화면이 이 자리를 강조한다.
`box`는 쪽 이미지(`width`×`height` 픽셀) 기준 `[x0, y0, x1, y1]`이다.

```json
{ "page": 1, "width": 1653, "height": 2339, "items": [{ "text": "물질안전보건자료", "box": [615, 221, 969, 265] }] }
```

OCR 쪽이 아니거나 OCR 기록이 없으면(이전 전처리) `items`가 비어 있고 `width`·`height`는 OCR 기록이 없을 때 `null`이다. `n < 1`이면 422.

### 4.7 `GET /api/documents/{id}/result` — 최종 결과

`status`가 `done`일 때만 200이고, 그 전에는 **409**다. 결과 파일이 없으면 404.

```json
{
  "to21": { "doc": { "...": "..." }, "msds": [ "..." ] },
  "needs_review": [ { "msds_index": 0, "section": 2 } ],
  "warnings": ["항목 분할 파일 없음: 임시 분할 (찾은 항 14/16, MSDS 1건)"],
  "schema_errors": ["msds.0.hazard...: ..."],
  "to21_validator": [ { "level": "경고", "rule": "V01", "field": "msds[0]...", "message": "..." } ]
}
```

| 칸 | 뜻 |
|---|---|
| `to21` | TO21 v0.6 문서(`expand.to_to21` 결과). 실패한 항은 빈 값. 모양은 TO21 스키마(저장소 밖, D-47)가 정한다 |
| `needs_review` | 사람이 볼 항: 실패, 검사 문제, 펼치기 문제, 그림문자 대조 불일치 |
| `warnings` | 입력·실행 경고 |
| `schema_errors` | TO21 스키마 검증 문장 (`validate_to21`) |
| `to21_validator` | TO21 검증기 V01~V23 결과 |

### 4.8 `GET /api/documents/{id}/sections/{m}/{no}` — 끝난 항의 값

`m`은 MSDS 순번(0부터), `no`는 항 번호(추출 대상 1·2·3·8·9·11·12·14·15). 문서가 끝나기 전에도 끝난 항의 값을 받는다.

```json
{
  "msds_index": 0, "section": 3, "title": "구성성분의 명칭 및 함유량", "pages": [1, 2],
  "status": "done", "needs_review": false, "reextracted": true, "seconds": 9.0,
  "errors": [], "check_problems": [],
  "parsed": { "...": "..." }
}
```

[항 칸](#52-문서-진행-상태-상세)에 아래가 더해지고, `errors`는 앞 3개가 아니라 전부다.

| 칸 | 뜻 |
|---|---|
| `check_problems` | 줄 번호·코드표 검사 문제 |
| `parsed` | **펼치기 전 중간 형식.** 실패한 항은 `null`. TO21 모양이 아니고 프롬프트에 따라 바뀐다. 미리 보기용이며 검수·수정의 기준은 `/result`의 `to21`이다 |

- 모델 응답 원문, 사용량, 요청 기록은 내보내지 않는다(`raw/` 파일에만 있다).
- `needs_review`는 호출·검사 기준이다. 펼치기 문제와 그림문자 대조 불일치까지 합친 최종 목록은 `/result`의 `needs_review`다.

| 오류 | 경우 |
|---|---|
| 404 | 없는 문서, 계획에 없는 항(항목을 나누기 전이거나 다시 돌린 직후 포함), 끝났는데 파일이 없음 |
| 409 | 그 항이 아직 끝나지 않음(`queued`, `running`). 다시 돌리는 중이면 이전 실행의 파일이 있어도 이렇게 답한다 |
| 422 | `m < 0`, `no`가 1~16 밖 |

### 4.9 `GET /api/documents/{id}/regenerated` — 재생성 MSDS

끝난 문서의 TO21 결과로 MSDS를 다시 만들어 추출 대상 항(1·2·3·8·9·11·12·14·15)만 항별 줄로 돌려준다. **모델을 부르지 않고** 저장도 하지 않는다.
만드는 일은 TO21 제공 `TO21_MSDS_DB적재_재생성_v0.6.py`가 하며, 저장소 밖 `to21/v0.6/`에서 읽는다(D-47).
10-26판은 빈 칸이 많은 문서에서 `KeyError`로 멈추므로 10-31판(기업 제공 폴더)을 쓴다.

```json
{
  "msds": [{
    "msds_index": 0,
    "header": ["물질안전보건자료 (MSDS)", "MSDS 번호: AA00845"],
    "sections": [{
      "section": 1, "title": "화학제품과 회사에 관한 정보", "status": "done", "needs_review": false,
      "lines": [ { "kind": "head", "text": "가. 제품명" }, { "kind": "item", "text": "염산(20%)" } ]
    }]
  }]
}
```

- `status`는 그 항의 추출 결과다. **`failed`인 항도 빈 양식으로 나오므로** 화면에서 실패를 함께 보여 줘야 한다.
- `needs_review`는 `/result`와 같은 최종 기준이다.
- 스크립트가 글자로 찍는 `None`은 `값 없음`으로 바꾼다. 숨김 줄은 빼고, 제목이 두 번 나온 항은 처음 제목으로 합친다.
- 결과는 HTML·PDF가 아니라 줄 목록이다. 화면이 그리고 PDF는 브라우저 인쇄로 만든다.

| 오류 | 경우 |
|---|---|
| 404 | 없는 문서, 결과 파일 없음 |
| 409 | `status`가 `done`이 아님 |
| 500 | 재생성 스크립트 실패 (파일 없음, 스크립트 오류). `detail`에 사유가 있다 |

### 4.10 `/api/documents/{id}/review` — 추출값 확인 기록

`done` 문서만 쓴다(그 전에는 409). 항별 칸, 근거, 검사 문제, 검수 기록을 함께 돌려준다. PUT도 바뀐 뒤의 전체 보기를 돌려준다.

```json
{
  "summary": { "sections_total": 9, "sections_confirmed": 1, "fields_total": 803, "fields_checked": 28, "fields_edited": 1 },
  "msds": [{
    "msds_index": 0,
    "info": { "product_name": "염산(20%)", "last_revision_date": "2023-11-24", "composition_type": "혼합물", "component_count": 2 },
    "sections": [{
      "section": 3, "title": "구성성분의 명칭 및 함유량", "status": "done", "pages": [3], "needs_review": false,
      "problems": [], "confirmed": null, "field_count": 57, "checked_count": 0,
      "groups": [{ "path": "components[0]", "title": "염산", "fields": [{
        "path": "components[0].cas_no", "label": "CAS 번호", "value": "7647-01-0", "display": null, "original": null,
        "state": "unchecked", "reviewer": null, "at": null, "page": 3, "source_text": "…", "problems": []
      }] }]
    }]
  }]
}
```

- `label`·묶음 `title`은 스키마 키나 코드가 아니라 우리말 이름이다(TO21 추출스키마 v0.6 칸 설명, 추출명세서 v0.6 코드표). `display`는 화면에 보일 값으로, 코드(`TX_ORAL` → `급성 독성(경구)`)·참거짓(`예`/`아니오`)을 말로 바꾼 것이다. 그대로 보이면 되는 칸은 `null`이고, 고칠 때는 `value`를 쓴다.
- 값이 있는 스칼라 칸만 보여 준다. 코드가 채우는 칸(`seq` 등), 원문 칸(`raw`, `text`), 빈 칸은 뺀다. 그래서 **비어 있는 칸은 아직 채울 수 없다.**
- `state`는 `unchecked`, `confirmed`(확인함), `edited`(수정됨)다.

`PUT .../review/fields` 본문: `{ "msds_index": 0, "path": "components[0].cas_no", "action": "confirm" | "edit" | "reset", "value": "...", "reviewer": "김검수" }`

- `edit`는 `value`가 필요하다. 원래 칸이 숫자면 숫자로 바꾼다. 빈 글자는 값 없음이다.
- 없는 칸은 404, 형식이 틀리면 422, 끝나지 않은 문서는 409.

`PUT .../review/sections` 본문: `{ "msds_index": 0, "section": 3, "confirmed": true, "reviewer": "김검수" }`

저장과 반영:

- 기록은 `data/service/<번호>/review.json`에 둔다(`fields`, `sections`, 변경 이력 `log`). 검토자는 브라우저가 보낸 이름이며 인증하지 않는다.
- **추출 결과 파일은 고치지 않는다.** `/result`는 늘 추출 그대로이고, 고친 값은 `/regenerated`를 만들 때만 얹는다.
- 다시 돌리면 칸 경로와 값이 달라지므로 기록을 `review.이전-<시각>.json`으로 옮겨 두고 새로 시작한다.
- 재생성 문서에 쓰이지 않는 칸도 있다. 예: `revision_no`를 고쳐도 문서는 `revision_label`을 찍는다.

### 4.11 `POST /api/documents/{id}/retry`

`failed`·`interrupted` 문서와, `done`이지만 실패한 항이 있는 문서를 처음부터 다시 돌린다(`can_retry`가 참인 문서). 진행 상태를 비우고(올린 파일·기준일은 유지) 대기열에 넣는다.

- **202**: 대기 상태의 문서 진행 상태
- **409**: 그 밖의 경우 (`queued`, `running`, 모든 항이 성공한 `done`). 동시에 여러 번 눌러도 한 번만 들어간다
- 같은 원본으로 다시 돌린다. 같은 문서 번호의 이전 실행 기록(`outputs/`, `checks/`, `raw/`)은 덮어쓰고, `timing.jsonl`은 뒤에 이어 붙는다.

| `validation` | 객체 또는 null | 추출 직후 최종 검증 요약 (모델이 뽑은 원래 값 기준. 검수해도 바뀌지 않는다) |

목록의 "9 / 9항"은 `counts.done / counts.total`이다. 항목을 나누기 전에는 `counts.total`이 0이다. 끝난 문서의 `counts.needs_review`와 항별 `needs_review`는 최종 검증의 검수 필요 항(펼치기 문제·검증기 위치 포함)을 따른다.

## 6. 오류 응답

FastAPI 기본 모양 `{ "detail": ... }`이다.

```json
{ "detail": "없는 문서: U-20990101-001" }
```

쿼리·경로 값이 틀린 422는 `detail`이 항목 목록이다.

```json
{ "detail": [ { "type": "literal_error", "loc": ["query", "status"],
                "msg": "Input should be 'all', 'active', 'done' or 'failed'" } ] }
```

프론트엔드의 `client.ts`는 이를 `ApiRequestError(status, code, message)`로 바꾼다.
`code`는 `http_<상태>`이거나 `validation`이다. 응답 모양이 `schemas.ts`와 다르면 `ApiContractError`가 난다.

## 7. 진행 이벤트 (서버 안쪽)

화면이 직접 받지는 않는다. 파이프라인이 `store.apply(id, event)`로 상태에 반영하는 이벤트이고,
응답의 칸이 어디서 오는지 알 때 참고한다. 반영 규칙은 `service/progress.py`의 `apply_event`에 있다.

| 이벤트 | 내는 곳 | 바뀌는 칸 |
|---|---|---|
| `queued` | `POST /retry` | 진행 칸을 모두 비움 |
| `started` | pipeline | `status=running`, `stage=preprocess` |
| `page` `{page, total}` | `render.preprocess(on_page=)` | `preprocess`, `page_count` |
| `preprocess_done` `{page_count, text_layer}` | pipeline | `text_layer`. 믿기 어려운 텍스트층이면 경고 추가 |
| `stage` `{stage}` | pipeline | `stage` (`sections`, `extract`) |
| `plan` `{msds_count, page_count, sections}` | `run_document(on_event=)` | `msds_count`, `sections` (모두 `queued`) |
| `section_started` `{msds_index, section}` | `run_document` | 그 항 `running` |
| `section_done` `{msds_index, section, ok, reextracted, needs_review, seconds, errors}` | `run_document` | 그 항 `done`/`failed` 등 |
| `finalize` | `run_document` | `stage=finalize` |
| `done` `{summary}` | pipeline | `status=done`, `stage=done`, `summary`, 경고 추가 |
| `failed` `{error}` | pipeline | `status=failed`, `error` |
| `interrupted` | 서버를 켤 때 (`store.recover`) | `status=interrupted` |

`run_document`의 `on_event`와 `render.preprocess`의 `on_page`는 선택 인자다.
주지 않으면 지금까지와 똑같이 동작한다(`scripts/run_sections.py` 등 기존 도구는 그대로).

## 8. 아직 없는 것

| 항목 | 지금 | 하려면 |
|---|---|---|
| OCR | 붙이지 않음. 텍스트층이 `글꼴깨짐`·`없음`·`혼합`이면 경고만 남긴다 | 전처리 뒤 필요한 쪽만 OCR → 출처 다시 고르기를 파이프라인에 넣는다 |
| 부분 결과 ("추출된 쪽부터 검수") | 끝난 항의 중간 형식은 4.8로 받지만, TO21 `/result`는 끝나기 전에 409 | 끝난 항만 펼쳐 돌려준다 |
| 한 항만 다시 추출 | 문서 전체만 다시 (`/retry`) | `POST /api/documents/{id}/sections/{m}/{no}/retry` |
| 빈 칸 채우기, 판정·저장 화면의 입력 | 값이 있는 칸만 고칠 수 있다 | 스키마에서 칸 목록을 받아 빈 칸도 내준다 |
| 화면이 쓰려던 칸 | `title`(1항 제품명), `grade`(실버·골드), `message`, `started_at`·`finished_at`, 쪽별 `pages[]`, 항별 `mode`·`attempts` | 화면에서 필요해지면 서버에 먼저 추가하고 `schemas.ts`를 맞춘다 |
| 취소 | 없음 | 작업자에 멈춤 신호를 두고 항별 호출 사이에서 확인한다 |
| 인증·사용자 | 없음. 검토자 이름은 브라우저에만 있다 | 서비스 전환 때 정한다 |
| 계약 시험 | 없음 (응답 11종을 zod로 한 번 확인함) | `/openapi.json`과 `schemas.ts`를 맞대는 시험을 둔다 |
