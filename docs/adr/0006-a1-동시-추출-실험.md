# A1 문서 동시 추출 수는 일관성 실험 후 결정한다

## 배경

`docs/2026-11-02-part-a-extraction-design.md` 4절은 처리 시간보다 결과 일관성을 우선한다. 문서 하나 안에서도 항별 모델 요청이 동시에 발생하므로 문서 동시 처리 수만으로 실제 모델 호출 수를 추정할 수 없다. 같은 모델·설정에서도 함께 처리되는 요청에 따라 출력이 달라질 수 있다.

## 제안

서로 다른 양식의 문서 3건 이상과 스캔본 1건 이상을 기준 문서로 고른다. 각 기준 문서를 단독으로 두 번 처리해 자연 변동을 측정하고, 각각 다른 문서 1·2·4건과 함께 제출해 비교한다. 캐시·기존 결과 재사용은 끈다. 기준일·모델 버전·프롬프트·코드·설정·입력 해시는 고정해 기록한다. TO21 v0.6 채점기로 첫 단독 결과를 기준 삼아 두 번째 단독 결과와 각 동시 결과의 항목별 점수를 비교한다.

동시 결과에 단독 반복의 기준 점수보다 낮은 항목이 없고 실제 동시 실행이 확인된 경우만 해당 조건을 후보로 둔다. 점수만으로 모든 칸이 같다고 증명할 수 없으며 채점기가 세지 않는 칸과 항목별 차이는 별도 점검해야 한다. 세 문서의 조건을 모두 확인하고 팀이 허용 기준을 정한 뒤 가장 큰 안전한 문서 동시 처리 수 N을 운영 설정으로 결정한다. 관찰 실패나 작업 실패를 성공으로 판정하지 않는다.

이 저장소에는 실험을 위한 `backend/scripts/experiment_a1_concurrency.py`를 둔다. 실제 추출 API에 작업을 제출하고 결과 JSON과 채점 비교를 저장한다. 각 대상에 대해 단독 두 번, 대상과 다른 문서 1·2·4개 묶음을 차례로 실행하므로 비용과 시간이 들며 테스트 전용 환경에서만 사용한다. 반드시 `--confirm-real-calls`가 필요하다. 대상 3건이면 총 36개 작업을 실제로 제출한다. 실험 전에 모델 호출 상한과 작업자 수를 기록하고, 대상과 동시 문서에 같은 파일을 쓰지 않는다.

```bash
cd backend
mkdir -p ~/to21-concurrency-results
.venv/bin/python scripts/experiment_a1_concurrency.py \
  --target /경로/일반1.pdf --target /경로/일반2.pdf --target /경로/스캔.pdf \
  --scanned-target 3 \
  --companion /경로/다른1.pdf --companion /경로/다른2.pdf \
  --companion /경로/다른3.pdf --companion /경로/다른4.pdf \
  --as-of 2026-11-02 --out ~/to21-concurrency-results/시험1 \
  --confirm-real-calls
```

API 기본 주소는 `http://127.0.0.1:8020`이고 `--url`로 바꿀 수 있다. 별도로 TO21 v0.6 채점기가 `to21/v0.6/`에 있어야 한다. 결과 디렉터리는 미리 없어야 하며 원본 추출 JSON이 들어가므로 공유·커밋하지 않는다. 실험 서버가 외부에 모델 요청을 보낼 수 있으므로 승인된 테스트 입력·모델만 사용한다.

보고서는 단독과 동시 실행의 항목 점수, 실패 상태, 요청 묶음의 경과 시간, 상태 폴링으로 관찰한 최대 동시 `running` 수와 단계별 관측 시간을 담는다. `running` 수는 응답을 순서대로 읽은 근사치이며 모델 호출의 실제 겹침을 보장하지 않는다. 단계 시간도 폴링 간격 오차가 있고 모델 서버 처리 시간 자체가 아니다. 전처리·모델 호출 시간을 정확히 분리하려면 작업자와 모델 서버의 타임스탬프 및 게이트 관측 기록을 별도로 확보한다. 진행 상태나 실제 호출 로그가 없다면 처리 속도나 N을 확정하지 않는다.

## 측정·결정 상태

- 실제 실험: **미실시**. 모델 서버·테스트 문서·채점기와 서버 설정을 갖춘 환경에서 실행해야 한다.
- 운영 N: **미결정**. 측정 전의 임의 숫자를 확정값으로 사용하지 않는다.
- 11쪽 문서의 전처리·모델 호출 시간 분리와 20건 목표 확인: **미실시**.
- 실측 결과, 모델 버전, 하드웨어, 입력 및 설정 해시, 시간별 호출 수, 실패·재시도, TO21 항목별 결과, 스캔 포함 여부를 검토하고 이 ADR을 갱신한다.
