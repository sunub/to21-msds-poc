# 단일물질 2항 판정은 지식DB 없이 지식 응답의 약속만 가정해 만든다

3단계(단일물질 2항 판정, `backend/src/msds/compliance/single.py`의 `compare_single`)는 지식DB의 기준 분류와 공급사가 2항에 적은 분류를 비교한다. 그런데 기준 분류를 줄 TO21 지식DB(PoC는 엑셀, 운영은 API)가 아직 없고, 지식 응답의 형태를 정하는 정합성검증 설계서 v0.2도 저장소에 없다(docs/adr/0001). 그래서 `knowledge.get_reference`의 임시 반환 형태를 "약속"으로 가정하고, 그 약속만 보고 판정 코드를 만들었다. 실제 데이터는 시험에서 가짜 제공자(`FakeProvider`)로 대신했다.

이 문서는 그 약속이 무엇인지, 무엇을 확인하지 못했는지, 실제 지식DB가 약속과 다를 때 무엇을 하는지를 남긴다.

## 정한 것

- **판정 코드는 지식을 직접 읽지 않는다.** `compare_single(inputs, provider)`는 provider 객체를 인자로 받는다. 실제 지식DB가 오면 provider만 새로 만들고 `compare_single`은 고치지 않는 것이 원칙이다.
- **지식이 완전하다고 가정하지 않는다.** 기준에 없는 분류를 공급사만 적으면 불일치가 아니라 근거부족이다. 지식이 없거나(`knowledge_version`이 None) CAS가 없으면 모두 근거부족이다. 지식DB가 비었거나 덜 채워져 있어도 공급사가 틀렸다고 단정하지 않는다.
- **판정 규칙은 2026-10-27 팀 결정이다.** 설계서 대신 정했고, 규칙 목록은 `single.py` 상단에 있다. 기준 1 ↔ 공급사 1B를 일치로 보는 방향은 질문 범위 밖이라 구현자가 정했다(세부구분 규칙을 양방향으로 적용).

## 가정한 약속

`get_reference(cas_no, as_of)`가 아래 형태로 답한다고 가정한다. 근거는 D 가이드 3.4의 예시이며 `knowledge.py` docstring에 "임시"로 적혀 있다.

```python
{
  "cas_no": str, "as_of": str | None,
  "knowledge_version": str | None,   # None 이면 "지식 없음"
  "classes": [{"class_code", "category", "route_form", "source"}],
  "ate": {...}, "un_no": ..., "source": ...,
}
```

| # | 가정 | 판정 코드에서 쓰는 곳 |
|---|---|---|
| A1 | CAS 하나로 조회하면 그 물질의 기준 분류 목록이 하나 온다 | 성분 1의 CAS로 한 번만 조회 |
| A2 | `class_code`는 TO21 스키마 v0.5 코드다(`HH_SKIN_CORR` 등) | 공급사 분류와 맞추는 키 |
| A3 | `category`는 공급사 쪽과 같은 원문 표기다(`1`, `1B`, `3(호흡기계자극)`). "구분" 글자가 붙지 않는다 | 구분 비교, 세부구분 판단(`\d[A-C]`) |
| A4 | 흡입 급성독성은 `HH_ACUTE_INHAL` + `route_form`(가스/증기/분진·미스트)으로 온다 | 비교 키 `(class_code, route_form)` |
| A5 | 지식이 있으면 `knowledge_version`이 문자열이고, 없으면 None이다 | 근거부족 여부 |
| A6 | `classes`에 없는 분류는 "기준에 기록이 없음"이지 "해당 없음이 확인됨"이 아니다 | 과잉 분류를 근거부족으로 둠 |
| A7 | 기준일(`as_of`)에 맞는 버전은 provider가 골라 준다 | 판정 코드는 기준일을 넘기기만 함 |

## 확인하지 못한 것 (한계)

- **실제 지식DB·실제 MSDS로 돌려 보지 않았다.** 시험의 기준 분류는 모두 시험 안에서 직접 넣은 값이다. 시험은 "약속을 지키는 데이터가 오면 규칙대로 판정하는가"까지만 보장한다.
- **실제 provider가 없다.** `knowledge.get_reference`는 `NotImplementedError`를 낸다. 실제로 돌릴 수 있는 것은 빈 지식을 돌려주는 `EmptyProvider`뿐이고, 이걸로 돌리면 모든 판정이 근거부족이다.
- **`load_inputs` → `product_type` → `compare_single` 연결을 실제 문서로 시험하지 않았다.** 단일물질 예제가 없다(25번 황산은 혼합물).
- **불일치 심각도가 없다.** 기준이 설계서에 있다.
- **원문 표기가 정규화되어 들어온다고 가정한다.** 공급사 쪽 `category`도 "구분 1"이 아니라 "1"로 추출된다고 본다(TO21 스키마의 약속).

## 실제 지식DB가 약속과 다를 때

### 대응 원칙

1. **provider에서 맞춘다.** 지식DB의 형태가 약속과 다르면 provider가 약속의 형태로 바꿔 돌려준다. `compare_single`과 그 시험은 그대로 둔다.
2. **판정 규칙을 바꿔야 하면 혼자 정하지 않는다.** 규칙 변경은 판정 결과를 바꾸므로 팀(또는 멘토링)에서 정하고, `single.py` 상단 규칙 목록, `tests/test_D_single.py`, 이 문서를 함께 고친다.
3. **변환에는 출처를 남긴다.** 코드 변환표나 정규화 규칙을 만들면 그 근거(TO21 명세서 코드표, 고시 별표 등)를 표나 docstring에 적는다.

### 가정별 대응

| # | 다를 때의 모습 | 대응 | 판정 규칙 변경 |
|---|---|---|---|
| A1 | 같은 CAS에 기준이 여러 개다(기관별·국가별·고시 개정본별) | **멈추고 확인한다.** 어느 기준을 쓸지는 TO21 결정이 필요하다(멘토링 질문). 정해지기 전까지 provider는 고시 기준 하나만 고르거나, 고를 수 없으면 `knowledge_version=None`으로 돌려 근거부족이 나오게 한다 | 고를 규칙이 정해지면 provider에만 넣는다 |
| A2 | 코드 체계가 다르다(예: PPT의 `GHS0206`, 한국어 분류명) | provider에 변환표를 둔다. 변환되지 않는 코드는 버리지 말고 `ETC_UNMAPPED`로 두어 근거부족이 나오게 하고, 목록을 F에게 넘긴다 | 없음 |
| A3 | 구분 표기가 다르다("구분 1", "Category 1", "1(A)") | provider에서 원문 표기 규칙(TO21 명세서 R01~R25)으로 정규화한다. 정규화 전 원문은 `source`나 별도 칸에 남긴다 | 없음. 단 `3(호흡기계자극)` 같은 부가 표기가 다르게 오면 정규화 규칙을 시험으로 고정한다 |
| A4 | 흡입이 경로별 코드로 온다(`GHS0203~0205`, `HH_ACUTE_INHAL_VAPOUR` 등) | provider에서 `HH_ACUTE_INHAL` + `route_form`으로 바꾼다. 분류 결과 계약(`ghs/models.py`의 `ClassificationDecision`)도 같은 이유로 경로별 코드를 거부한다 | 없음 |
| A5 | 버전 정보가 없다 | provider가 파일 이름·수정일·해시로 버전 문자열을 만든다. 데이터를 읽었으면 None으로 두지 않는다 | 없음 |
| A6 | 지식DB가 "분류되지 않음(해당 없음)"을 명시적으로 기록한다 | 그 기록이 있는 분류에 한해 과잉 분류를 불일치로 바꿀 수 있다. **판정 규칙 변경이므로 원칙 2를 따른다** | 있음: 과잉 분류 규칙과 해당 시험 |
| A7 | 지식DB에 시행일·버전 날짜가 없다 | 기준일 판단을 할 수 없음을 provider docstring과 판정 결과의 `knowledge_version`에 남긴다. 구버전 MSDS 판정은 "참고"로 보고한다 | 없음 |
| 기타 | 약속에 없는 칸이 있다(근거 시험값, 기관명 등) | 판정에 쓰지 않으면 무시하고, 화면·설명에 쓸 만하면 `source`에 담는 방안을 E와 정한다 | 없음 |

### 지식DB가 왔을 때 할 일 (순서)

1. 엑셀의 칸을 위 A1~A7과 하나씩 대조해 다른 점을 표로 적는다.
2. 다른 점마다 위 표의 대응을 고른다. 판정 규칙 변경이 필요한 항목은 F에게 넘겨 결정을 받는다.
3. 실제 엑셀에서 몇 행을 잘라 provider 시험을 만든다(약속 형태로 돌려주는지). TO21 자료이므로 저장소에 올리지 않는 규칙(D-47)을 지킨다.
4. `tests/test_D_single.py`가 고치지 않고 그대로 통과하는지 본다. 고쳐야 했다면 원칙 1을 어긴 것이므로 이유를 이 문서에 남긴다.
5. 골드 중 단일물질 문서로 `load_inputs` → `product_type` → `compare_single`을 돌린다. 불일치와 근거부족을 사람이 원문과 대조해, 지식DB 문제인지 공급사 MSDS 문제인지 판정 규칙 문제인지 나눠 적는다.

## 다른 방안과 비교

- **지식DB가 올 때까지 3단계를 보류한다:** 판정 결과 형태가 정해지지 않아 6·7단계와 혼합물 비교(5단계)가 모두 늦어진다. 약속이 바뀌면 provider에서 흡수할 수 있으므로, 지금 만드는 비용이 더 작다.
- **기준에 없는 분류를 불일치로 본다:** 지식DB가 불완전하면 맞는 MSDS를 틀렸다고 판정한다. 지식의 완전성을 확인할 방법이 없어 채택하지 않았다(A6).
