# B2 판정 테이블 준비

이 SQL은 판정 기록을 저장할 `judge` 스키마의 테이블을 만든다. 판정 API나 판정 엔진을 설치하거나 실행하지는 않는다.

PostgreSQL 컨테이너가 실행 중이고 `deploy/htodb/.env`를 준비한 상태에서 저장소 루트에서 실행한다. 아래 절차는 **새 DB 또는 `judge` 테이블이 아직 없는 DB**를 위한 것이다. 기존 테이블이 있다면 먼저 구조와 마이그레이션 이력을 확인한다. 기존 데이터 삭제나 테이블 변경을 수행하지 않는다.

```bash
docker compose --env-file deploy/htodb/.env -f deploy/htodb/compose.yaml exec -T pg \
  psql -v ON_ERROR_STOP=1 -U kdb -d kdb -c 'CREATE SCHEMA IF NOT EXISTS judge'

for migration in \
  backend/migrations/b2_0004_judge_runs_versions.sql \
  backend/migrations/b2_0005_judge_explanations_reviews.sql \
  backend/migrations/b2_0006_judge_snapshots_artifacts.sql; do
  docker compose --env-file deploy/htodb/.env -f deploy/htodb/compose.yaml exec -T pg \
    psql -v ON_ERROR_STOP=1 -U kdb -d kdb < "$migration" || break
done
```

세 SQL은 순서대로 한 번 적용한다. 오류가 나면 이후 SQL을 실행하지 않으며, 이미 성공한 SQL은 유지되므로 원인을 확인하고 남은 SQL만 적용한다. 사용자 환경에 맞는 DB 및 권한 설정은 별도로 준비해야 한다.

```bash
docker compose --env-file deploy/htodb/.env -f deploy/htodb/compose.yaml exec -T pg \
  psql -U kdb -d kdb -c '\dt judge.*'
```

`runs`, `versions`, `explanations`, `reviews`, `snapshots`, `artifacts` 여섯 테이블이 보이는지 확인한다. 이 절차는 HTODB 원본 데이터나 PDF 추출 결과를 복사하지 않는다.
