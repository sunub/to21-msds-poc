# version1 ~ version9 추출 방법 정리

`data/pages/version*` 각각이 어떤 코드로, 어떤 방법으로 만들어졌는지 정리한다. 전용 스크립트가 없는 버전은 어떤 함수가 그 역할을 했는지 표시했다.

## 한눈에 보기

| 버전 | 만든 코드 | 핵심 방법 | 표 `\|` 묶기 | 줄번호(`L001`) |
|---|---|---|:---:|:---:|
| version1 | `preprocess.py` + `render.py`(`render_pdf`) / `ocr_paddle.py` | PDF 텍스트(PyMuPDF) 추출 + 200DPI 이미지 렌더링. OCR은 별도 파일(`pNNN_ocr.txt`)로만 저장, 병합 안 함 | ✗ | ✗ |
| version2 | `ocr_batch_version2.py` | PDF 텍스트(신뢰도 1.0) 우선 + 안 겹치는 부분만 PaddleOCR로 보강(bbox 겹침 ≥0.25 제거), 좌표 재정렬 | 옵션(기본 ✗) | 옵션(기본 ✗) |
| version3 | `ocr_batch_version3.py` | 페이지 이미지 + PDF 후보 + Paddle 후보, 셋을 **Qwen3-VL-4B**에 넣어 최종 원문을 모델이 대조·전사 | - | - |

## 버전별 상세

### version1 — PDF 텍스트 + 이미지 렌더링 (OCR 별도 파일)
- 코드: `backend/scripts/preprocess.py` → `backend/src/msds/preprocess/render.py`의 `render_pdf()`
- PyMuPDF로 PDF에서 페이지별 텍스트(`pNNN.txt`)와 200DPI 이미지(`pNNN.png`)를 뽑는다. 텍스트층 상태(`없음`/`글꼴깨짐`/`정상`)를 분류만 하고 OCR은 아직 안 함.
- 텍스트층이 안 좋은 페이지는 `backend/scripts/ocr_paddle.py`가 따로 PaddleOCR을 돌려 `pNNN_ocr.txt`라는 **별개 파일**로 저장한다. version2 이후처럼 하나의 텍스트로 합치지 않는다.

### version2 — PDF 텍스트 + PaddleOCR 하이브리드 (기준 방법)
- 코드: `backend/scripts/ocr_batch_version2.py`
- PDF 좌표 텍스트를 신뢰도 1.0 기본값으로 쓰고, 텍스트층이 정상이면 PaddleOCR 결과 중 겹치지 않는 부분만 추가. 텍스트층이 없거나 깨지면 페이지 전체를 PaddleOCR로 처리.
- `pipe_rows`(표 `|` 묶기), `line_numbers`(`L001` 줄번호) 옵션이 있지만 **기본값은 둘 다 꺼짐**. version2/version7은 이 기본값 그대로 실행됐다.

### version3 — VLM(Qwen3-VL-4B) 대조 전사
- 코드: `backend/scripts/ocr_batch_version3.py`
- 페이지 이미지, PDF 텍스트 후보, Paddle 텍스트 후보 세 가지를 프롬프트에 같이 넣고 Qwen3-VL-4B에게 "이미지를 기준으로 최종 원문을 결정하라"고 시킨다. 읽기 순서·띄어쓰기·숫자·코드·표의 행 관계를 보존하도록 프롬프트에 명시돼 있다. version2까지의 규칙 기반 방식과 달리 **모델이 최종 판단**을 내린다.

### version4 — version2 + 표 묶기 고정
- 코드: `backend/scripts/ocr_batch_version4.py` (내부에서 `ocr_batch_version2.main`을 그대로 가져다 씀)
- `pipe_rows=True`만 고정해서 호출. 로직은 version2와 동일, 표가 `|`로 묶여 나온다는 점만 다르다.

### version5 — C→B 전달 규격 포장
- 코드: `backend/scripts/build_c_to_b_contract.py` (기본 인자: `--source-root version4 --output-root version5`)
- 새로 OCR을 돌리지 않는다. version4 산출물을 읽어서 `msds.preprocess.c_pipeline.group_rows`로 좌표 기반 행을 다시 구성하고, 줄번호를 매겨 `data/pages/version5`, `data/sections/version5`, `data/codes/version5`라는 B에게 넘기는 최종 규격으로 재작성하는 **후처리/포장 단계**다.

### version6 — 재OCR(묶기+줄번호) + 재포장
- OCR 코드: `backend/scripts/ocr_batch_version6.py` — version2 로직에 `pipe_rows=True`, `line_numbers=True`를 고정해 처음부터 다시 추출, 결과는 `data/pages/version6_ocr`.
- 포장 코드: `build_c_to_b_contract.py --source-root data/pages/version6_ocr --output-root/--sections-root/--codes-root version6` — version5와 같은 포장 로직을 version6_ocr 결과에 적용해 `data/sections/version6`, `data/codes/version6` 생성.

### version7 — version2 재현성 확인 (이번 세션)
- 코드: 별도 파일 없이 `ocr_batch_version2.main(output_version="version7")`을 그대로 호출 (옵션은 전부 기본값).
- 목적: "지금 version2 코드를 다시 돌리면 같은 결과가 나오는가"를 확인하기 위한 재실행. 통계(페이지 241, PaddleOCR 추가 1,729줄, 검토대상 193줄)가 version2와 완전히 일치함을 확인했다.

### version8 — 표 묶기 재현 + 테스트 1건
- 코드: `backend/scripts/ocr_batch_version8.py` (이번 세션에 작성)
- version2/version7이 `pipe_rows=False`로 돌아서 표 묶기가 안 됐던 걸 발견하고, `pipe_rows=True`를 고정한 재현 가능한 스크립트로 만듦. 처음엔 T21-025(황산) 1건만 테스트. 이후 `line_numbers=True`도 추가해 `L001` 줄번호까지 켬.

### version9 — version8 방법으로 전체 20건
- 코드: `ocr_batch_version8.py --output-version version9 --force` (스크립트는 version8과 동일 파일, 출력 폴더 이름만 인자로 다르게 줌)
- manifest에 있는 20개 문서 전체를 `pipe_rows=True`, `line_numbers=True`로 재추출. 총 241페이지, 245.67초 소요(`data/pages/version9/timing_report.md`에 문서별·페이지별 시간 기록).

## 메모

- version1~6은 전부 이번 세션 이전에 이미 저장소에 있던 코드다 (내가 만든 게 아님). version7~9만 이번 세션에서 실행/작성했다.
- version4, version6, version8, version9는 전부 **같은 핵심 로직(version2)에 옵션만 다르게 준 것**이다. 완전히 다른 방법은 version3(VLM)뿐이다.
- version5, version6의 "version6" 부분은 OCR 산출물이 아니라 **포장 단계 산출물**이라 `version6_ocr`(OCR)과 `version6`(포장)이 서로 다른 폴더임에 주의.


- 참고 version 3 -> B에게 version10이라고 한 뒤에 드렸다.
