# version12 방법 정리

version9(PDF 텍스트 + PaddleOCR, pipe_rows, 줄번호)을 기본으로 쓰고, **표만** Docling(GPU, TableFormer)의 실제 표 구조로 교체한 버전.

## 왜 만들었나

- **version9**: 모든 줄을 y좌표 근접도(12px 허용오차)로 묶어서 `|`로 join. 표처럼 보이는 줄끼리는 대체로 잘 묶이지만, 어디까지나 "위치가 비슷하면 한 행"이라는 추정이라 경계가 없는(테두리 없는) 다단 표에서는 줄이 엉뚱하게 합쳐지거나 한 논리적 행이 둘로 쪼개지는 문제가 있었음.
- **version11**: 전부 Docling(레이아웃+TableFormer 모델)로 다시 뽑음. 실제 표 구조(행/열/셀)를 모델이 인식해서 표가 있을 땐 정확하지만, 테두리/격자선이 없는 표는 레이아웃 모델이 "표"로 인식을 못 해서 일반 본문처럼 읽기 순서대로 풀어버림 → 그런 페이지에서는 version9보다 결과가 더 나쁨 (T21-002 p002 사례).
- **version12**: 그래서 "본문은 version9, 표만 Docling"으로 역할을 나눔. 테두리 없는 표라도 version9의 y좌표 묶기가 이미 꽤 잘 처리하고 있었기 때문에, **Docling이 표로 확실히 인식하고 우리 추출 결과와 매칭이 되는 경우에만** 그 부분을 Docling 그리드로 바꾸고, 나머지는 전부 version9 그대로 둬서 회귀가 없도록 설계.

## 코드

- 파일: `backend/scripts/ocr_batch_version12.py`
- `ocr_batch_version2.py`의 `pdf_lines`, `paddle_data`, `coverage`, `norm`, `find_pdf`, `VERIFIED_IMAGE_TEXT`를 그대로 import해서 재사용 — OCR/텍스트 추출(entries 생성) 로직은 version9와 완전히 동일.
- Docling 쪽은 `do_table_structure=True`, `do_ocr=False`(우리는 이미 자체 PDF+Paddle 텍스트가 있으므로 Docling 자체 OCR은 끔), GPU(`AcceleratorDevice.CUDA`)로 설정.

## 동작 순서 (페이지 단위)

1. **entries 생성** — version9와 동일하게 PDF 텍스트 우선 + 안 겹치는 PaddleOCR 결과만 추가.
2. **Docling 표 감지** — 텍스트층이 "정상"인 문서에 한해서만, 같은 PDF를 Docling으로 변환해 `TableItem`의 그리드(행×열 셀 텍스트)를 페이지별로 모아둠. (`docling_tables_by_page`)
   - 텍스트층이 없는 문서(이미지/글꼴깨짐)는 애초에 Docling 표 로직을 돌리지 않고 100% version9 그대로 둠 — 매칭 기준이 될 원본 텍스트가 없어서 억지로 매칭하면 오히려 품질이 떨어지기 때문.
3. **매칭 (`match_table_to_entries`)** — 감지된 표의 셀 텍스트들을 정규화해서, 우리 entries 중 텍스트가 정확히 일치하는 것들을 찾음. **일치하는 셀이 70% 미만이면 매칭 실패로 보고 그 표는 버림** (해당 영역은 version9 방식 그대로 유지).
4. **병합 (`entries_to_text_with_tables`)**:
   - 표에 매칭된 entries는 일반 행 묶기 대상에서 제외.
   - 나머지 entries는 version9와 동일한 y좌표 행 묶기(`entries_to_text`와 동일 로직)로 처리.
   - 매칭된 표는 Docling 그리드를 그대로 `|`로 join한 여러 행으로 교체.
   - 둘을 각 블록의 평균 y좌표로 다시 정렬해서 원래 읽기 순서를 복원하고, `line_numbers=True`면 전체에 `L001...`을 다시 매김.

## 결과 (20개 문서, 241페이지 전체 실행)

| 구분 | 수치 |
|---|---|
| Docling이 감지한 표 | 73개 |
| entries와 매칭에 성공해 Docling 그리드로 교체된 표 | 68개 |
| 매칭 실패해 version9 그대로 둔 표 | 5개 (T21-006 2개, T21-023 2개, T21-045 1개) |
| 텍스트층이 없어 Docling을 전혀 안 돌린 문서 | T21-002, T21-005, T21-043, T21-S003 (이 문서들은 version9와 100% 동일) |

- 출력 위치: `data/pages/version12/`
- 각 문서 `summary.json`/`config.json`에 `docling_tables_matched`, `docling_tables_detected` 페이지별 집계 포함.

### 처리 시간 (재측정, 타이밍 버그 수정 후)

| 구분 | 수치 |
|---|---|
| 전체 문서 처리 시간(20개 문서 `document_total_seconds` 합) | 274.33초 |
| 그중 Docling 표 감지 시간 | 34.66초 |
| 평균 | 1.138초/페이지 (241페이지) |
| 감지/매칭 (재측정) | 75개 감지 / 68개 매칭 |

version12는 **모든 페이지에서 PaddleOCR을 돌리기 때문에**(version9 방식 그대로) version13(필요한 페이지만 OCR)보다 느림.

## 한 줄 요약

**본문/비정형 줄 = version9(PDF+Paddle, y좌표 묶기), 테두리 있고 Docling이 실제로 표로 인식+매칭되는 부분만 = Docling TableFormer(GPU) 그리드.** 매칭이 안 되거나 텍스트층이 없으면 무조건 version9로 안전하게 폴백해서 version9보다 나빠지는 페이지가 없도록 만듦.
