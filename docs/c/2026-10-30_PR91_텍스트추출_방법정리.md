# PR #91 — 텍스트 추출 방법 정리 (`backend/src/msds/preprocess/`)

PR #91(`origin/main`에 이미 merge됨, 최종 커밋 `21031e8`)이 만든 텍스트 추출 파이프라인을 정리한다. 별도 설명 문서는 없고, 코드 자체(머리말 docstring + `PREPROCESS_VERSION` 히스토리 주석)에 아주 상세히 적혀있어서 이걸 근거로 재구성했다.

> 참고: 이 방법은 제가 만든 version1~12(OCR 실험)와는 **다른, 더 발전된 별도 파이프라인**이다. version1~12는 거의 빈 스켈레톤 위에서 독자적으로 진행된 작업이고, PR #91은 팀의 진짜 메인 브랜치(`origin/main`)에서 나온 정식 구현이다.

## 핵심 파일 4개와 역할

| 파일 | 줄 수 | 역할 |
|---|---:|---|
| `render.py` | 336 | 전체 흐름 지휘자. PDF→이미지/텍스트/표, 텍스트층 상태 판별, 겹쳐찍기 제거, 입력 출처 선택, 표 md 저장까지 전부 호출 |
| `layout.py` | 390 | 읽기 순서 복원(recursive XY-cut), 글자 재조립, 줄바꿈 이어붙이기, 표 칸 격자화 |
| `ocr.py` | 316 | PaddleOCR 실행과 보완(항목명\|값 칸 묶기, 기호 오인식 되돌리기) |
| `source.py` | 58 | 그 페이지는 텍스트층을 믿을지 OCR을 믿을지 결정 |

## 1. `render.py` — 전체 흐름

`preprocess(pdf_path, doc_id, dpi=150)`가 입구다. 페이지마다:

1. `layout.page_lines()` + `layout.page_tables()` + `layout.char_items()`로 원재료 추출
2. `layout.reading_text()`로 읽기 순서 텍스트 생성 → `p001.txt` (모델 입력)
3. `drop_overstrike()`로 겹쳐찍기 사본 제거 → `p001.match.txt` (원문 대조용)
4. `judge_page()`로 텍스트층 상태 판별(정상/글꼴깨짐/이미지만/빈쪽)
5. `_pick_source()`가 "정상"인데도 텍스트층이 못 미더운 페이지는 OCR로 전환 (`source.choose`) → `p001.ocr_input.txt`
6. `_write_tables()`가 데이터 표만 골라 `tables/p002_t1.md`로 별도 저장

**출력**: `p001.png`(이미지), `p001.txt`(모델 입력), `p001.match.txt`(원문대조), `p001.ocr_input.txt`(OCR 전환 시), `tables/*.md`(데이터 표), `meta.json`(판별 근거 전부 기록).

### 텍스트층 상태 판별 기준 (`judge_page`/`judge_doc`)
- **정상**: 그대로 믿음
- **글꼴깨짐**: ① 한글 'ㄴ'받침 자리에 'ㄲ'받침이 비정상적으로 많음(폰트 매핑 깨짐) ② 한글·영문 아닌 기호가 대부분
  - 기준값: 20건(2026-10-24) 실측, 정상 문서 최대 0.012 vs 깨진 문서 0.69 → 0.05로 설정
- **없음**: 전 페이지 이미지뿐(스캔본) / **혼합**: 일부만 이미지뿐
- `follow_doc()`: 글자 수가 적어 페이지 단위로 판정 못 한 "정상" 페이지는 **문서 전체 판정을 따름** (같은 문서는 같은 폰트라 깨짐도 같다는 전제)

### `PREPROCESS_VERSION` — 버전 변경 이력 (주석으로 계속 누적)
입력(p001.txt)이 달라질 때마다 버전 문자열을 올리고, `meta.json`과 실행 기록에 남겨서 **어떤 버전의 입력으로 추출을 돌렸는지 추적**(`extract/runner.py`가 버전 불일치 시 추출을 막음):
```
2026-10-27-xycut              저장 순서(get_text) → 읽기 순서로 변경
2026-10-27-xycut-tables       선으로 그린 표의 행을 칸 순서대로 한 줄로
2026-10-27-xycut-tables-ocrpick  텍스트층 못 믿는 정상 페이지는 OCR 글로 전환
2026-10-28-chars              텍스트층을 줄이 아니라 글자 좌표로 재조립
2026-10-28-chars-wrap         칸 글이 다음 줄로 넘어간 걸 그 칸에 이어붙임
2026-10-29-wrap-mincol (현재) 좁은 열(라벨)은 다음 줄을 잇지 않음
```

## 2. `layout.py` — 읽기 순서 복원 (recursive XY-cut)

**문제의식**: PDF에 저장된 글자 순서가 사람이 읽는 순서와 다를 수 있다(예: S001 2쪽은 2번 항목 본문이 1번보다 먼저 저장돼 있음).

**알고리즘**(`_cut()`):
1. 영역을 가로지르는 빈 띠 중 **가장 넓은 곳**부터 자르고, 나뉜 양쪽을 재귀적으로 다시 자름
   - 가로 띠(줄 사이 공백) → 위/아래로 분할
   - 세로 띠(글자 높이의 `GUTTER`=1.0배 이상) → 좌/우로 분할(단 나누기)
   - 단, 세로로 나눈 양쪽의 줄 높이가 서로 맞으면(`_aligned()`) 이건 단이 아니라 "항목명\|값"이나 표의 한 행이므로 자르지 않음
2. 더 못 자르면 세로 중심 기준으로 줄로 묶어서 위→아래, 줄 안에서는 왼→오 순으로 읽음

모든 기준값(`SHRINK`, `GUTTER`, `ALIGNED` 등)은 고정 픽셀이 아니라 **그 페이지 글자 높이 중앙값(h)의 배수**로 잡혀있다 — 문서마다 양식이 달라서.

**표 처리**:
- `page_tables()`: PyMuPDF가 찾은 "선으로 그린 표"의 칸 격자 좌표를 가져옴
- `_table_rows()`: 표의 한 행에 든 글자 조각들을 칸 순서대로 이어붙여 하나의 조각으로 변환(칸 사이는 공백 두 칸) — 칸 안 줄 간격과 행 간격이 같아서 좌표만으로 행 경계를 못 가릴 때(M005 2쪽 사례) 이 방식으로 해결
- `is_data_table()`: 데이터 표(성분표 등, 3열 이상+머리글 있음) vs 단순 "항목\|값" 틀을 구분 — 데이터 표만 `tables/*.md`로 별도 추출
- `continue_grid()`: 앞 페이지에서 이어지는 표인데 이 페이지엔 열 선이 없는 경우(M013 3쪽), 앞 페이지 열 자리를 재사용

**글자 재조립** (`char_items`, `join_wrapped`):
- 한 줄이 글자/띄어쓰기/문장부호 여러 레이어로 겹쳐 찍힌 문서(M013: "64742945"와 "- -"가 따로 나옴) 대응 → 줄 단위가 아니라 **글자 좌표로 직접 재구성**, 같은 자리 중복 글자는 사본으로 보고 하나만 남김
- `join_wrapped()`: 칸 값이 다음 줄로 넘어간 경우(성분 표의 긴 이름 등) 위 줄의 그 칸에 이어붙임. 단, 라벨처럼 좁은 열(`MIN_WRAP_COL` 미만)은 잇지 않음(M013 6·7쪽에서 "LD50" 아래 "경피"/"흡입" 라벨이 잘못 이어붙던 문제 수정 — 이게 가장 최근 버전 변경 사유)

## 3. `source.py` — 텍스트층 vs OCR 선택

글꼴 판정이 "정상"이어도 텍스트층을 못 믿을 페이지가 있음(M013: 글자/띄어쓰기/문장부호가 다른 레이어로 겹쳐 찍혀 "점막과눈그리고경피로…"처럼 붙어버림; 039번 1쪽: 표가 그림으로만 들어가 텍스트층에 내용 자체가 없음).

**판별 방법**: 텍스트층과 OCR 결과의 **어절 일치율(F1 score)**을 비교. 기준값 `WORD_AGREE_MIN = 0.75`(개발 문서 실측: 정상 페이지 최소 0.784 vs M013 최대 0.679로 그 사이에서 설정). OCR 결과가 아예 없는 페이지는 그냥 텍스트층을 씀.

## 4. `ocr.py` — PaddleOCR 보완

- 깨진 텍스트층을 대신할 글자를 PaddleOCR로 생성(300dpi, 모델 입력용 이미지는 별도 150dpi)
- `group_cells()`: MSDS 본문 대부분이 "왼쪽 항목명 | 오른쪽 값" 2열 구조라는 점을 이용해, OCR이 준 줄 단위 결과를 칸으로 재조립(값이 여러 줄이면 묶어서 한 칸으로)
- `fix_symbols()`: PaddleOCR 오인식 교정(예: ℃→C, ℃→°c 같은 기호 오인식 되돌리기)
- 실측 결과(S003, 2026-10-26, paddleocr 3.7.0): 원문 조각 44개 중 42개 일치, 틀린 2개는 전부 ℃ 오인식

## 5. `extract/` 연동

- `extract/runner.py`: 추출 실행 시 입력 페이지의 `meta.json`에 기록된 `preprocess_version`이 **지금 코드의 `PREPROCESS_VERSION`과 다르면 추출을 막음** — 버전이 다른 입력으로 잘못 추출하는 걸 방지
- `extract/client.py`: 모델에 보낼 때 그 페이지가 텍스트층 출처인지 OCR 출처인지(`input_source`) 표시

## 요약 한 줄

**"PDF 글자 조각의 좌표만 보고, 그 페이지에 맞는 기준값(h의 배수)으로 재귀적으로 영역을 쪼개서 사람이 읽는 순서를 복원한다. 표는 선 정보로 칸을 나누고, 텍스트층을 못 믿는 페이지만 OCR로 바꿔치기한다."** — version1~12가 PDF-텍스트/PaddleOCR을 "좌표 근접도로 줄을 묶는" 비교적 단순한 방식이었다면, PR #91은 XY-cut 기반으로 레이아웃 자체를 재귀적으로 분석하는 훨씬 정교한 방식이다.
