# 1주차 기술 명세서

- 버전: v0.2 (2026-10-25, 계획서 v0.4와 맞춤: 프롬프트 시험 3건 D-46, TO21 자료 보관 D-47, 검사 실패 시 신뢰도 D-45)
- 함께 볼 문서: 1주차 실행 계획서(노션), 결정기록(노션). 본문의 D-번호는 결정기록의 번호다.
- 이 문서는 "어떻게"를 정한다. 계획서가 누가·언제·무엇을·왜를 정한다면, 이 문서는 역할 사이에 오가는 파일의 형식, 함수의 입력과 출력, 실행 명령, 끝났는지 확인하는 방법을 정한다.

**실행 위치:** 코드는 `backend/` 아래에 있다. 이 문서의 `python scripts/...`와 `pytest` 명령은 `backend/`에서 실행한다. `data/`, `runs/`, `to21/`, `.env`는 저장소 최상위에 있고, `src/msds/common/paths.py`가 이 위치를 알고 있다.

**원칙:** 역할 사이에 오가는 것과 여러 역할이 같이 쓰는 코드는 이 저장소에 **동작하는 상태로** 들어 있다. 각 역할 안쪽의 일은 **입력·출력과 할 일이 적힌 함수 뼈대**로 들어 있고, 담당이 채운다. 공용 코드를 바꿔야 하면 혼자 고치지 말고 디스코드에 먼저 공유한다.

## 2. 공통 약속

### 2.1 문서 번호와 manifest (`data/manifest.csv`, `src/msds/common/manifest.py`)

- 문서 번호: TO21 방식. 첫 50건은 번호 그대로(25번 → `T21-025`), 추가 50건은 `T21-S003`, `T21-M001`.
- manifest는 사람이 확인한 기준표다. 스크립트가 자동으로 고치지 않는다(전처리는 다른 점만 알려 준다).

| 열 | 값 |
|---|---|
| doc_id | `T21-S016` |
| source_file | 원본 파일 이름 (확장자 포함). `data/raw/`에서 이 이름으로 찾는다. 한글 정규화(NFC/NFD) 차이는 무시한다 |
| folder | 받은 폴더 |
| purpose | 개발 / 평가 / 기타 (D-34) |
| pages | 쪽수 |
| text_layer | 정상 / 글꼴깨짐 / 없음 / 혼합 (TO21 `doc.text_layer`와 같은 값) |
| language | ko / en / mixed |
| input_mode | 이미지+글자 / 이미지만 (D-44) |
| reviewer, cross_checker | 검수 담당, 교차 확인 담당 (D-41) |
| note | 메모 |

### 2.2 경로 (`src/msds/common/paths.py`)

TO21 제공 자료는 저장소에 올리지 않고 각자 `to21/v0.5/`에 받아 둔다(D-47, 목록은 `to21/README.md`). `to21_file(kind)`는 파일이 없으면 받는 방법을 알려 주며 멈춘다.

경로는 직접 조립하지 말고 이 모듈의 함수를 쓴다. `page_png(doc_id, n)`, `page_txt(doc_id, n)`, `page_meta(doc_id)`, `silver_path(model_tag, doc_id)`, `silver_review_path(...)`, `review_sheet_path(doc_id)`, `gold_path(doc_id)`, `gold_unreviewed_path(doc_id)`, `run_dir(run_name)`, `to21_file(kind)`.

### 2.3 전처리 결과 (`data/pages/<문서번호>/meta.json`)

```json
{"doc_id": "T21-S016", "source_file": "...pdf", "page_count": 9, "dpi": 150,
 "text_layer": "정상", "language": "ko", "input_mode": "이미지+글자",
 "totals": {...}, "pages": [{"page": 1, "state": "정상", "image_cover": 0.0, "chars": 1200, ...}]}
```

쪽 상태(state): 정상 / 글꼴깨짐 / 이미지만(스캔 쪽) / 빈쪽. 텍스트층 판별 방법은 `src/msds/preprocess/render.py` 머리말에 있다.
2026-10-24에 20건으로 확인한 결과: 43번·S003만 글꼴깨짐, 나머지는 정상(S013의 11쪽은 로고만 있는 빈 쪽).

### 2.5 모델 응답 형식 (`schema.bundle_response_schema`)

```json
{
  "doc": {"language": "ko", "msds_count": 1},                 // b1만
  "msds": [ { ...그 묶음의 키만... } ],
  "evidence": [
    {"msds_index": 0, "field": "components[0]", "page": 2,
     "source_text": "벤젠 | 71-43-2 | 99.9 이상",
     "rules": ["R04"], "note": "'99.9 이상'을 R04에 따라 하한 99.9(>=)로 나눔"}   // rules·note는 실버만
  ]
}
```

- `field`는 msds 항목 안의 경로다. 목록은 항목 단위(`components[0]`), 단일 칸은 칸 단위(`meta.last_revision_date`).
- 합치기(`common.merge.merge_bundles`)가 evidence를 TO21의 `msds[].evidence`로 옮긴다(method="vLM"). rules·note는 TO21 형식에 칸이 없어 `.review.json`으로 따로 저장한다(D-33).

### 2.6 실버 결과

- `data/silver/<모델>/<문서>.json`: TO21 스키마 v0.5 그대로.
- `data/silver/<모델>/<문서>.review.json`: `[{bundle, msds_index, field, page, source_text, rules, note}]`

### 2.7 칸과 경로 (`common.jsonpath`, `common.align`)

검수표·투표·성적표가 모두 같은 "칸"을 써야 결과가 맞물린다.

- **칸 하나**: 숫자 묶음(Q)·측정 조건(COND)·서술 문장(STMT)은 통째로 한 칸. 글자 목록(동의어 등)도 한 칸. 나머지는 끝 값까지 펼친다.
- **키 경로**: 목록은 순서가 아니라 "무엇인지"로 짝짓는다(TO21 채점기와 같은 기준).
  `regulations[3].applicable` → `regulations[k=7664-93-9|OSH|OSH_MEASURE|].applicable`
  성분은 CAS(없으면 이름), 규제는 성분·법령·항목, 독성은 성분·항목·지표·동물종 등. 전체 목록은 `align.LIST_KEYS`.
- 주요 함수: `keyed_flatten(msds_item)`, `unflatten_keyed(pairs)`, `item_path_map` + `to_keyed`(근거의 번호 경로 → 키 경로), `generic(path)`(번호·키를 지운 경로), `jsonpath.to_cell / from_cell`(엑셀 칸 ↔ 값).
- 한계: 키가 같은 항목이 여러 개면 나온 순서로 `#2`, `#3`을 붙인다. 이때만 순서에 따라 짝이 바뀔 수 있다.

### 2.8 우선순위 (`common.priority.priority_of`, D-32)

키 경로를 넣으면 1·2·3을 돌려준다. 물성은 필수 9종이면 1, 독성은 급성(경구·경피·흡입)이면 1, 규제는 국내 법령(OSH·KREACH·CCA·DG·WASTE)이면 1.

### 2.9 검수표 (`src/msds/review/sheet_spec.py`, D-36)

- 시트 `검수`: 열 이름과 순서는 `COLUMNS` 그대로. 검수 결과 드롭다운은 `RESULT_OPTIONS`(GPT 채택 / Claude 채택 / 수정 / 삭제 / 누락 추가).
- 시트 `문서 정보`: 문서 번호, 원본 파일, 쪽수, MSDS 순번, 검수 시작·끝 시각, 검수자, 교차 확인자.
- 경로 열은 `msds[i].` + 키 경로.
- **두 모델이 모두 비워 둔 칸은 행을 만들지 않는다.** 두 모델이 함께 빠뜨린 항목은 개수 세기로 찾아 "누락 추가" 줄을 직접 넣는다.
- 수정값: 객체·목록은 한 줄 JSON으로 적는다. 숫자처럼 보이는 글자를 글자로 남기려면 따옴표로 감싼다(`"01"`).
- 검수 결과를 비워 둔 칸은 미검수다. 골드에는 `DEFAULT_MODEL`의 값이 들어가고 `.unreviewed.json`에 기록되며 성적표에서 "참고"로 표시된다(D-35). `DEFAULT_MODEL`은 프롬프트를 고정한 뒤 25번 실버를 TO21 정답 예제로 채점해 점수가 높은 모델로 A가 정한다.

### 2.10 골드

- `data/gold/<문서>.json`: TO21 스키마 그대로. `doc.extraction.engine = "manual(gold)"`.
- 근거: 검수표의 원문 조각·쪽(수정이면 수정 원문 조각·쪽). method="수기", needs_review=false (D-36).
- `data/gold/<문서>.unreviewed.json`: 미검수 칸 경로 목록.
- 완성 조건: TO21 스키마 통과, TO21 검증기 "오류" 0건.

## 3. 모델 호출 (`src/msds/extract/client.py`, D-44)

- 교육원 키는 **MonoRouter**(`https://monogpt.kr/api/monorouter/v1`), RunPod은 **vLLM**. 둘 다 OpenAI 호환 **Chat Completions**다. 같은 코드로 부르고 `configs/models.yaml`의 모델 이름만 바꾼다.
- 입력: 쪽마다 `=== 쪽 N ===` + 텍스트층(이미지+글자 모드이고 그 쪽이 정상일 때) + 쪽 이미지(base64 PNG).
- 구조화 출력은 `structured` 순서대로 시도한다.
  - `json_schema`가 거부(400 등)되면 `json_object`, 그다음 `none`으로 넘어간다. 받아들여진 방식은 기억해 다음 호출부터 바로 쓴다.
  - 응답은 묶음 응답 스키마로 검증하고, 실패하면 오류 목록을 붙여 `max_retries`번 다시 요청한다.
  - 그래도 실패하면 읽을 수 있는 JSON은 넘겨서 쓸 수 있는 부분은 쓰고, 오류는 기록에 남긴다.
- 출력 길이 한도에 걸리면(`finish_reason=length`) 그 묶음은 실패로 기록한다. 대응은 묶음을 더 쪼개거나 `max_tokens`를 늘리는 것이다(계획서 14장).
- 대체 모델: 실패하면 `fallback_models` 순서로 한 번 더 시도한다(Claude: fable-5 → opus-5, 기준선: Qwen3.8 → Qwen3.6).
- 출력 한도 이름: GPT-5 계열은 `max_completion_tokens`(`token_param`으로 설정). 400 오류에 max_tokens가 언급되면 자동으로 바꾼다.

### 10/25 아침 점검 (B): `python scripts/check_router.py`

모델마다 글자 / 이미지 / json_schema / json_object 호출을 한 번씩 해 표로 보여 주고 남은 크레딧을 조회한다. 결과를 디스코드에 공유한다.

### 기준선 서버 (B)

시작점(모델 카드의 vLLM 레시피를 우선한다):

```bash
vllm serve Qwen/Qwen3.8-27B --max-model-len 131072 --limit-mm-per-prompt '{"image": 40}' --gpu-memory-utilization 0.92
```

- 문서 한 건을 통째로 넣으므로 입력이 길다(150dpi 기준 쪽당 대략 수천 토큰, 17쪽 문서는 수만 토큰). `--max-model-len`과 쪽 이미지 수 한도(`--limit-mm-per-prompt`)를 문서 쪽수에 맞춘다. 39번(37쪽)은 2주차 평가용이라 1주차에는 해당 없다.
- 생각 모드는 `configs/models.yaml`의 `chat_template_kwargs: {enable_thinking: false}`로 끈다. 이 모델에서 이 이름이 맞는지 모델 카드로 확인한다.
- 서버 주소는 `.env`의 `VLLM_BASE_URL`(예: `http://<pod 주소>:8000/v1`).

## 4. 프롬프트 (`src/msds/extract/prompts/`, `prompt_builder.py`)

**구성**: 한 번 호출할 때 아래를 이어 붙인다.
1. `system.md`: 역할, 입력 설명, 모든 칸에 적용하는 원칙(보이는 것만, 없으면 null, 원문 그대로, 목록 빠짐없이 등)
2. `output_silver.md` 또는 `output_baseline.md`: 근거(evidence) 작성법. 실버만 규칙 번호·설명을 추가로 요구한다(D-37)
3. `b1.md`~`b5.md`: 이번 묶음 안내 + TO21 명세서에서 꺼낸 [필드 정의] [규칙] [공통 구조] [코드표] [동의어]
4. (b2~b5) `[성분 목록]`: b1 결과로 만든 성분 번호 목록
5. 문서 전체 쪽

**만드는 법**: `b1.md`~`b5.md`는 `python scripts/build_prompts.py`로 TO21 명세서에서 만든다. 직접 고치지 말고 `prompt_builder.py`의 `GUIDES`(묶음 안내)나 규칙 목록을 고친 뒤 다시 만든다. TO21이 명세서를 고치면 다시 만들기만 하면 된다.

**원칙 (D-43, D-46)**
- 프롬프트는 개발용 3건으로 시험한 뒤 고정한다: S016(단일물질, 독성 정보 많음), M013(혼합물, 성분 8개·함유량 범위·쪽을 넘는 성분 표), S003(텍스트층 깨짐, 쪽 이미지만 입력). 평가용 문서(25번 포함)는 프롬프트를 고정한 뒤에만 돌리고, 그 결과를 보고 프롬프트를 고치지 않는다. 스크립트가 `--allow-eval` 없이는 평가용 문서를 돌리지 않는다.
- 평가용 문서의 내용을 예시로 넣지 않는다. 1주차 프롬프트는 예시 문서 없이 규칙만 쓴다.
- 참고: TO21 명세서의 "예시(가상)" 값 일부(황산, 7664-93-9 등)가 25번 문서와 겹친다. 명세서 원문이라 그대로 두었고, 25번 점수를 해석할 때 이 점을 함께 적는다.
- 프롬프트를 고치면 `PROMPT_VERSION`(p1 → p2 …)을 올린다. 실행 기록에 버전이 남는다.

**2주차 변형 프롬프트 (D-40)**: 규칙은 그대로 두고 읽는 순서와 방법만 바꾼다(예: 표를 먼저 행 단위로 옮겨 적은 뒤 채우기). `output_*.md`처럼 파일을 하나 더 두고 runner에 선택 인자를 추가하는 방식으로 넣는다.

## 6. 검수하는 법 (검수 전원)

계획서 13장(검수 가이드)이 기준이다. 엑셀에서는 아래만 기억한다.
- `우선순위` 1부터, `일치`가 불일치·한쪽만인 줄부터, `원문 대조`가 불일치인 줄부터 본다.
- `검수 결과`를 고른다. 수정이면 `수정값`·`수정 원문 조각`·`수정 쪽`을 적는다.
- 두 모델이 함께 빠뜨린 항목은 맨 아래에 새 줄을 넣고 `검수 결과`를 "누락 추가"로, 경로는 같은 종류의 다른 줄을 참고해 적는다.
- `문서 정보` 시트에 검수 시작·끝 시각을 적는다.
- 판단이 어려우면 `메모`에 적고 디스코드에 공유한다. 혼자 정하지 않는다.
