## 해결한 것

- 실제 모델 설명의 명백한 오류 2종 (2026-11-04, 22번 일부): `claim_problems`에 두 검사를 더함. ① 15항 경계 줄에 방향을 말하면 문제("더 강하게·약하게", "높게 적었다", "과기재했다" 등. T21-M005 유독물질). "더 높게 걸쳐", "과기재인지 확정할 수 없다", "과대분류 여부는"처럼 경계를 바르게 설명한 말은 걸지 않는다. ② 쉼표가 든 성분 이름을 쉼표에서 나눠 '앞부분와 뒷부분' 두 성분처럼 쓰면 문제(T21-M013 '포름알데히드, polymers with …'). 앞부분 바로 뒤에 접속사와 뒷부분 첫 낱말이 이어질 때만 보고, 다른 이름 안에 든 글자('파라포름알데히드와')나 줄여 쓴 이름('Methane과')은 걸지 않는다. 원인은 모델만이 아니라 원인 글이 성분 이름을 ", "로 이어 붙이는 데 있다(엔진 쪽, 고치지 않음). 영향: 실제 설명 219개(측정 3회, 모델이 쓴 글 179개) 중 이 2건만 걸림. 추출 결과 325개(평가용 제외, 25번 예제 포함)의 설명 요청 3,055건(중복 포함, 서로 다른 요청 1,375건) 문장틀은 하나도 걸리지 않음(검증자 측정). 막는 범위는 흔한 모양뿐이다: "강하게 적었"("더" 없음), "과다 기재", "더 엄격하게 적용했다", 띄어쓰기 없이 붙인 이름, 번역한 이름은 지나간다. 반대로 "과기재일 수도 있고 누락일 수도 있다" 같은 바른 문장이 걸리면 문장틀로 간다(판정은 그대로). 문장틀은 이 검사를 거치지 않고 저장된다. 요청 해시는 그대로라 저장된 설명은 다시 만들지 않는다.
- 실제 모델 설명 측정과 화면 시험 (2026-11-04, 6·34번, 화면은 검토까지·저장과 리포트는 API): RunPod L40S(약 70분, 약 $1.3)에 `qwen36_35b_runpod_48g`를 띄웠다. ① 브라우저로 개발용 T21-S016을 업로드 → 추출(75초) → 추출값 확인 → "판정으로 넘기기"(201) → 판정·설명 4건 → 검토 4건 → 저장 → PDF 리포트까지 됐다. 저장 화면은 아직 자리만 있어(10번) 저장·리포트는 API로 했다. ② TO21 25번 예제와 개발용 10건의 설명 73건을 쟀더니 요약 46건이 ":"였다. 원인은 문법 강제 출력과 약한 요약 검사이고, 고친 뒤 73건 모두 모델 설명, 71건은 처음에 통과, 글 없는 요약 0건(T-26). 평가용 10건은 쓰지 않았다(D-43).
