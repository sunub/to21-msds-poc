## 해결한 것

- 한국어 시각 시험 실패 (2026-11-04, 23번): 코드 문제가 아니었다. 이 환경의 기본 Node 22.23.2(ICU 78.2)만 `AM`을 내고, 프로젝트 기준 Node 24(`.nvmrc`)에서는 통과한다(T-25).
- TO21 재생성 스크립트가 3.11에서 안 읽힘 (2026-11-04, 9번): 공용 TO21 창구가 3.11에서는 명령줄 실행용 `main()` 앞까지만 읽는다(B-15). 재생성 시험 3건과 `/regenerated` API가 3.11에서 동작한다. 팀 Python 전환은 하지 않는다.
- 판정 실패와 "근거부족(시스템)"(4번), 멘토링 확인(11번), 결정 대기 13~17번 (2026-11-03): 기업 미팅이 더 없어 확인을 기다리지 않고 직접 정한 결정으로 확정했다. 시스템 장애는 판정으로 저장하지 않고 판정 실패로 둔다(B-12). 멘토링 항목은 `mentoring-followups.md` 그대로. 데이터 등급(Q-02)·구버전 제외(Q-01)는 지금 처리 유지, 읽기 모드·정답 축적·지식 버전 재판정(Q-11~13)은 PoC 범위 밖.
- 위험물 이유 글과 함량 하한 (2026-11-03): 32번. 이유 글에 최종 판정과 다른 "→ 경계"·"사람 확인"을 적지 않고 경계 조건만 적는다. 가연성 액체량·도료류 예외는 혼합물에만 붙인다. "입자가 없는 액체"처럼 바로 뒤에 없다고 쓴 고체 단어는 고체 단서로 보지 않는다(실제 데이터 0건, 검증 중 만든 사례). `sec15._expected`가 주석과 달리 하한 없는 함량("1% 미만")을 0부터로 보지 않던 것도 고침. 함유하면 해당(`≥0`)인 기준에서만 결과가 바뀐다(실제 DB: 탈크 보정 2행, 인 12185-10-3 산안법 금지, CAS 없는 물질 1개).
