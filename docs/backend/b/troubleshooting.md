## T-01 PDF에서 판정 줄이 오류 없이 사라짐

**증상:** 실버 20건 중 12건의 PDF에서 판정 줄이 빠짐 (당시 표·CSS 코드 기준의 검증 보고. 이 코드는 커밋 전이라 재실행해 볼 수 없고, 나중 코드를 영역 770으로 돌리면 건수가 다르다. 건수보다 기제가 중요하다). 응답은 200이고 오류 없음. 심각도 순 정렬이라 가장 중요한 줄부터 빠질 수 있음. HTML에는 줄이 다 있음.

**발견:** 독립 검증이 HTML과 PDF의 행을 대조해 발견. 그때까지의 시험은 25번 문서에서 PDF가 열리는지만 봐서 통과했음.

**조사 과정:**

| 순서 | 가설 | 확인 | 결과 |
|---|---|---|---|
| 1 | 표가 쪽 경계에 걸리면 줄을 잃는다 | 표를 줄 단위 블록으로 교체 | **틀림.** T21-010이 여전히 108줄 중 75줄 |
| 2 | 글꼴 축소(`subset_fonts`)나 저장 단계에서 잃는다 | 단계별로 줄 수 측정 | **틀림.** 단계 전후 같음 |
| 3 | CSS가 원인이다 | `<style>`만 제거 | 108줄 나옴. 조건은 맞지만 원인은 아님 |
| 4 | 특정 CSS 규칙이 원인이다 | 규칙·글자 크기별 측정 | `font-size:10pt`만 유실. 9pt·10.5pt·11pt는 정상 |
| 5 | 줄 끝이 영역 끝에 정확히 닿으면 쪽을 안 넘긴다 | 최소 재현, `filled` 값, MuPDF 소스 | **맞음** |

**단서:**
- 사고 난 쪽의 `filled`가 2356. A4 높이(842)를 넘고, 36 + 770×3 + 10과 일치
- 사고 난 쪽의 마지막 줄 끝이 정확히 806 (영역 끝). 정상인 쪽은 805, 796
- 10pt 줄 40개 높이에 영역을 맞추면 200줄 중 79줄. 0.37pt만 바꾸면 200줄

**원인:** MuPDF `html-layout.c`의 쪽 넘김 계산.

```c
avail = page_h - fmodf(box->s.layout.b - page_top, page_h);
if (line_h > avail) /* 다음 쪽으로 */
```

줄 끝이 영역 끝과 같으면 나머지가 0이라 `avail`이 쪽 높이 전체가 된다. 쪽을 넘기지 않아 뒤 줄이 쪽 밖에 놓이고, `draw`에서 잘리며, 오류는 없다. 10pt는 줄 높이가 정확히 12.0이라 잘 겹쳤다. **스키마나 판정 데이터와 무관**하다. 프로젝트 데이터 없이 재현된다. 소스는 1.27.0·1.28.0, 재현은 설치본 MuPDF 1.28.5로 확인. 독립 검증 보고에 따르면 float32 모의 계산이 1,440건의 남는 줄 수를 모두 맞혔다 (산출물은 임시 폴더라 남아 있지 않다). 명목상 어긋난 값에서도 누적 오차로 드물게 일어나고, 줄뿐 아니라 여백·테두리 끝이 닿아도 일어난다.

**해결:** 1차로 영역 높이를 769.63으로 바꾸고 재시도했으나 버그가 있는 기능을 피해 가는 방식이었다. 최종적으로 Story를 빼고 `reports._wrap`·`_layout`에서 줄 배치와 쪽 넘김을 직접 한다.

**재발 방지:** 최종 PDF에서 글을 다시 읽어 모든 줄이 순서대로 있는지 대조하고(`_first_missing`), 빠지면 422로 거절. 시험: `test_어떤_글자_크기에서도…`, `test_영역_높이에_줄이_정확히_맞아도…`, `test_실버_전체의_PDF에…`.

**배운 점:**
- 표를 없애도 줄이 사라지는 것을 재현하기 전에 "표가 원인"이라고 기록한 것은 성급했다.
- 판정 줄 수만 세는 검사는 의견에 "판정 일치"가 있으면 누락을 가린다. 글 전체를 순서대로 대조해야 한다.

## T-02 PDF에서 `㎥`가 네모로, 긴 글자가 잘려서 나옴

**증상:** `0.2 mg/㎥`가 `0.2 mg/□`로 찍힘 (재생성 줄 기준 실버 7건 `㎥`, 1건 `㎟`). 띄어쓰기 없는 긴 글자가 쪽 폭을 넘으면 뒷부분이 사라짐 (숫자·쉼표는 약 84자, `A`는 64자). `😀`가 `ὠ`로 찍힘. 글자 그대로의 `&amp;` 유실.

**발견:** T-01의 전체 글 대조를 넣자 드러남. 판정 줄 수만 셀 때는 보이지 않았다. 재생성 MSDS의 노출기준 줄이라 단위가 사라지면 값의 뜻이 바뀐다.

**원인:** Story가 CSS 없을 때 고른 글꼴(Charis SIL 등)에 묶음 단위 글자가 없음. 긴 글자 잘림과 엔티티 유실의 Story 내부 원인은 미확인.

**해결:** Story 제거. `Font("korea")`는 `㎥` 등을 모두 갖고 있어 원문대로 찍힌다. 줄은 글자 폭을 재서 직접 나눈다. 글꼴에 없는 글자는 `_for_font`에서 처리한다.

| 입력 | PDF |
|---|---|
| `10⁻³` (글꼴에 `⁻` 없음) | `10^-3` |
| `C₅` (글꼴에 `₅` 없음) | `C_5` |
| `∙` (실버 4건), `−`, `µ`, `‑` 등 | `·`, `-`, `μ`, `-` |
| 분해 한글(맥 파일명), 호환 한자 | NFC로 정리 |
| `😀`, Symbol 글꼴 문자 U+F0B3 | `[U+1F600]`, `[U+F0B3]` |

**재발 방지:** `test_글자_처리`, `test_특수_글자가_PDF에서…`, `test_띄어쓰기_없는_긴_글자도…`.

## T-03 T21-010 재생성 MSDS만 "만들지 못함"

**증상:** 리포트의 재생성 부분이 `TypeError` 한 줄로 대체됨. 판정 표는 정상.

**조사:** TO21 스크립트 469행 `_re.match(..., ln)`의 `ln`이 `None`. `extras`를 비우면 통과, `title_raw`의 `None`을 빈 글자로 바꿔도 통과 (MSDS 2건이 각각 362줄, 376줄).

**원인:** 스크립트가 빈 `title_raw`를 줄 목록에 넣은 채 `extras`를 처리하다 멈춤. 실버 추출본의 빈 값이 조건.

**해결:** TO21 파일은 고치지 않고 `reports._without_empty_titles`가 입력 사본에서 빈 글자로 바꿈. 넘김 기록 원본은 그대로.

**재발 방지:** `test_T21_010도_재생성_MSDS가_나온다`.

**남은 한계:** A쪽 재생성 API에는 같은 문제가 남아 있어 A2에 인계함.

## T-04 TO21 재생성 스크립트가 Python 3.11에서 안 읽힘

**증상:** `SyntaxError: f-string expression part cannot include a backslash` (514행 `main()`). main의 `test_E_regenerated`에서 2건이 같은 이유로 실패 (2 failed, 8 passed, main에서 실행). **이 작업과 무관한 기존 실패**다.

**해결:** B 리포트는 `def main():` 앞까지만 읽어 실행 (`reports._load_regen`). 쓰는 함수는 그 앞에 있다.

**남은 한계:** A쪽 `/api/documents/{id}/regenerated`는 현재 환경에서 실패할 수 있다. A2 인계. TO21이 스크립트를 고치면 우회를 지운다.

## T-05 지식DB 장애가 근거부족 판정으로 저장됨

**증상:** 조회 중 DB 연결이 끊기면 예외 없이 근거부족이 1건에서 45건으로 늘고 상태는 "판정 있음". 복구 뒤 같은 값을 다시 넘겨도 버전이 안 늘고, 다른 작업도 이 결과를 재사용.

**원인:** 엔진의 지식 조회가 예외를 잡아 "사유"로 돌려줌 (`class_lookup_db.py`, `regulation.py`). 처음에 넣은 연결 확인은 시작 시점만 봐서 부족했다.

**해결:** 엔진 파일은 고치지 않고 `judge.py`의 `_WatchedRepo`가 조회 오류를 기록해 `judge()`가 예외를 낸다. 화면에는 `판정 실패`로 보인다.

**재발 방지:** `test_조회_오류가_한_번이라도…`, `test_조회_중_지식DB_장애는…`.

**참고:** 설계서 14장("근거부족(시스템)")과 다르다. 개요 4절(같은 입력이면 같은 결과)을 따른 결정이다 (B-12).

## T-06 고친 값을 판정하기 전에 저장되어 저장본이 두 값을 섞음

**증상:** 값을 고친 넘김이 판정 전이어도 옛 버전 번호로 저장 성공. 저장본이 넘김 2와 판정 버전 1을 가리켜 리포트에 새 추출값과 옛 판정이 함께 나옴.

**원인:** 저장이 `seen_version`만 확인함. 1차 수정 뒤에도 확인 시점과 읽는 시점 사이에 새 넘김이 끼어드는 경합이 남음 (검증 보고: 끼워 넣기 없는 경쟁 250회 중 1회).

**해결:** 최신 넘김을 아직 판정하지 않았으면 검토·저장을 409로 막고, 저장은 확인한 번호의 넘김을 읽는다. 화면과 리포트도 판정과 같은 값의 넘김을 읽는다 (`_handoff_of_version`).

**재발 방지:** `test_판정_전_값으로는…`, `test_저장_중_끼어든_넘김은…`, `test_판정_전에는_화면과_리포트가…`.

## T-07 늦게 끝난 옛 넘김이 최신 판정을 덮음

**증상:** 처리가 늦은 넘김 2가 넘김 3 뒤에 끝나 최신 판정이 옛 값이 됨. 상태는 "판정 있음". 값이 그대로라 새 버전을 안 만든 넘김 3의 경우에도 발생.

**원인:** "무엇이 최신인지 정하기"와 "완료 표시"가 서로 다른 트랜잭션에 있어 그 틈에 끼어듦.

**해결:** 작업별 잠금과 한 트랜잭션 안에서 함께 처리. 이미 끝난 넘김은 다시 처리해도 기록이 바뀌지 않음.

**재발 방지:** `test_늦게_끝난_옛_넘김은…`, `test_값을_되돌린_넘김_뒤에…`, `test_값이_같은_넘김과_옛_넘김이…`, `test_끝난_넘김을_늦게_다시_처리해도…`.

## T-08 거짓 골드 등급

**증상:** 세 경우에 실제로는 아닌데 골드로 나옴. 칸 수를 개수로만 빼서 생긴 오계산, 골드 저장 뒤 값을 고치거나 검토를 되돌린 경우, 칸이 없는 문서.

**해결:** 칸을 경로로 대조하고, 최신 저장본이 지금의 값·판정·검토 기록과 같을 때만 골드. 저장 뒤 무엇이든 바뀌면 다시 저장할 때까지 실버.

**재발 방지:** `test_칸_수는_경로로…`, `test_골드는_지금_값과…`, `test_저장_뒤_검토가_바뀌면…`, `test_칸이_없는_문서는…`.

## T-09 모델 오류·이상한 응답에 설명이 "작성 중"에 멈춤

**증상:** 모델 서버 오류, 창구 오류, 또는 저장 못 할 글자(NUL)가 응답에 있으면 설명이 영원히 "작성 중". 10분마다 재시도.

**해결:** 호출·저장 실패를 모두 문장틀로 대체하고 이유를 `check_failures`에 남김.

**재발 방지:** `test_모델이_예외를_내도…`, `test_창구가_죽어도…`, `test_저장_못_할_글자를_쓴…`.

## T-10 AI 설명이 엔진과 다른 결론을 말해도 검사를 통과

**증상:** "판정은 일치입니다. 계산 결과는 구분 3입니다"가 불일치 건에서 통과. 개요 4절의 "실패로 볼 것"에 해당.

**원인:** 숫자 검사는 값이 요청 어딘가에 있으면 통과시킨다. 구분 3이 MSDS 쪽에 있어서 통과.

**해결:** `claim_problems`가 판정 문장과 계산 결과 문장을 대조. 1차 수정은 값이 없는 칸에서 검사를 건너뛰는 허점이 있어 (검증 보고: 실버에서 같은 모양 72줄) 다시 고쳤다.

**남은 한계:** 흔한 문장 모양만 본다. 실제 모델로 돌린 적이 없다 (`open-issues.md`).

## T-11 엑셀 수식 실행과 제어 문자로 인한 내려받기 실패

**증상:** 성분의 CAS 칸이 `=HYPERLINK(...)`이면 엑셀에서 수식이 됨. 의견에 `\x0b`가 있으면 저장은 되지만 엑셀이 계속 500이고, 이벤트는 지울 수 없어 그 작업의 엑셀이 영구히 막힘. U+FFFF도 같음.

**해결:** 모든 칸을 `_safe`로 통과시켜 수식을 글자로 바꾸고 제어 문자를 지움.

**재발 방지:** `test_제어_문자와_수식이…`, `test_이상한_글자도…`.

## T-12 시험 때문에 기존 시험이 깨지거나 멈춤

## T-15 옛 사본을 기준으로 계약을 고쳐 main과 어긋남

**남긴 한계:** 설명 검사는 여전히 문장 모양 검사이며 약하다. 검토자가 새로 쓴 반대 문장 20개 중 4개만 걸렀다. 패턴을 늘려도 다른 표현이 계속 지나가므로 여기서 멈췄다. 실제 모델 응답으로 측정한 뒤 방식을 다시 정한다 (open-issues 22). 그때까지 설명의 `checked=true`를 "엔진과 결론이 같음"의 보장으로 읽으면 안 된다. 저장소까지 함께 끊기면 실패 기록을 남기지 못해 임대 시간 뒤 다시 잡히고, 같은 작업이 이런 장애를 3번 맞으면 멈춘다 (새 넘김 또는 SQL로 복구).

## T-19 A1 창구를 붙였더니 설명 호출이 멈출 수 있었음

**증상:** A1 브랜치(`feat/a1-workflow`)와 합쳐 상한을 1로 두면 설명 호출이 끝나지 않는다. 2 이상이면 끝나지만 호출 하나가 자리 둘을 쓴다.

**원인:** A1의 `ChatClient`가 호출마다 `slot_sync("extract")`를 잡는데, B도 바깥에서 `slot_sync("explain")`을 잡았다. 계약 README는 "쓰는 쪽이 잡는다"는 모양이라 양쪽 다 계약대로 짠 셈이다.

**숨어 있던 이유:** B는 `model_gate`에서 `gate`를 가져오는데 A1이 내보내는 이름은 `get_model_gate`다. `ImportError`를 임시 창구로 돌리는 코드 때문에 조용히 넘어갔다. 이름만 맞췄다면 바로 멈췄다.

**해결:** A1 모듈이 있으면 바깥에서 잡지 않는다 (B-35). 우선순위 `explain`은 A1의 한 줄 수정이 필요해 요청으로 남겼다.

**함께 고친 것:** A1 문서가 여러 프로세스를 지원하므로, T-18에서 "한 프로세스 가정"으로 남긴 `recover()`가 실제 문제가 됐다. 공유·배타 잠금으로 다른 프로세스가 살아 있으면 건드리지 않게 했다 (B-33).

**검증:** 임시 작업 공간에서 합쳐 `tests/contracts`와 A1 시험 336개 통과, 앱 시작·종료 확인. 실제 모델은 부르지 않았다.

**시험 충돌:** 검토자와 내 pytest가 같은 `judge_test`를 비워 거짓 실패 5건이 났다. 같은 자원을 쓰는 검증은 하나씩 돌린다.

## T-20 엔진 규칙을 TO21 수락 시험과 설계서로 맞춤

**증상:** TO21 시험 P02에서 흡입 증기가 TO21은 구분4인데 우리는 분류안됨이었다.

**원인:** 2-부톡시에탄올의 환경부 분류가 `흡입:가스 구분3`인데 액체 물질이다. 혼합물 경로는 형태가 안 맞는다고 건너뛰고 고용노동부 `증기 구분4`를 썼다. D-22를 단일물질 경로에만 넣었던 탓이다 (T-16). 고친 뒤 ATEmix가 TO21과 같은 12.76이 됐다.

**틀린 가설:**
- "부등호 문장의 숫자 칸을 `=`로 읽는 것은 버그다" (지식DB 문서 검증에서 나옴). TO21 패키지 파서가 같은 동작이고 시험도 요구한다. 코드를 고치지 않고 질문으로 돌렸다.
- 처음 쓴 교차 확인이 항상 분류안됨을 냈다. `value_to_category`는 한글 경로를 받는다. 황산 예제 시험 하나는 우연히 통과했고, "같으면 경고 없음" 시험이 잡았다.

**판단:**
- 혼합물 표기 + 성분 1개를 설계서대로 불명확으로 두면 실버 5건의 2항 판정이 전부 사라진다. 실제로는 유해 성분만 적은 혼합물이라 혼합물로 두고 질문으로 남겼다.
- MSDS의 혼합물 11항 값에는 공급사 계산값이 섞여 있다 (`1649 mg/kg GHS 첨가식에 따라 계산`, ATE 범위). 그대로 쓰면 MSDS를 자신과 비교하게 되어 실측만 쓴다.

**재발 방지:** `tests/contracts/test_engine_to21.py`. 수정마다 실버 전체를 수정 전과 비교했다 (CSV 1812줄, 실제 HTODB 1939줄).
