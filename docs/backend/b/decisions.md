## PDF 판정 줄 유실 원인 (2026-11-02 규명, 독립 검증 반례 없음)

- **원인:** MuPDF `html-layout.c`의 `avail = page_h - fmodf(y - page_top, page_h)` (`flush_line`, 여백·표 행에도 같은 식). 줄·여백·테두리 끝이 영역 끝에 닿으면 나머지 0이라 "쪽 한 장이 통째로 남음"으로 계산되어 쪽을 넘기지 않는다. 뒤 줄은 쪽 밖에 놓여 `draw`에서 잘리고 오류는 없다. 위치가 계속 맞으면 쪽 몇 장 또는 나머지 전체가 사라진다. float32 누적 오차로 명목상 어긋난 값에서도 드물게 일어난다.
- **스키마·판정 데이터와 무관:** 프로젝트 데이터 없이 재현된다. 데이터는 줄 수로 닿는 위치에만 영향을 준다.
- **왜 10pt였나:** 줄 높이가 정확히 12.0이고 영역 높이가 770이라 위치가 정확히 겹친다. CSS는 조건이었고 근본 원인이 아니다.
- **근거:** 10pt 줄 40개 높이에 영역을 맞추면 200줄 중 79줄, 0.37pt만 바꾸면 200줄. 독립 검증의 float32 모의 계산이 1440건의 남는 줄 수를 모두 맞혔다. 소스는 1.27.0·1.28.0, 재현은 설치본 MuPDF 1.28.5.
- **대응 (2026-11-02):** `reports.py`에서 Story를 없애고 `_wrap`·`_layout`으로 직접 배치한다. 그래서 위 코드 경로를 거치지 않는다. Story에서 함께 드러난 긴 글자 잘림, 묶음 단위 글자 네모(`0.2 mg/□`), 글자 그대로의 `&amp;` 유실도 사라졌다.
- **글자 처리 (`_for_font`):** NFC로 정리하고, 보이지 않는 글자를 지우며, 연속 공백을 하나로 줄인다. 글꼴에 없는 첨자는 `10^-3`, `C_5`처럼 풀어 쓰고, 뜻이 같은 글자는 바꾸며 (`−`→`-`, `µ`→`μ`, 소프트 하이픈→`-`), 찍어서 다시 읽히지 않는 글자는 `[U+1F600]`처럼 코드값으로 보인다. HTML·엑셀·JSON은 제어 문자만 공백으로 바꾼다. 조사 과정은 `troubleshooting.md` T-01·T-02·T-14.
- **안전장치:** 최종 파일에서 글을 다시 읽어 모든 줄이 순서대로 있는지 대조하고, 빠지면 PDF를 내지 않는다 (API 422).
- **표:** `_Table`로 판정·성분 표를 직접 그린다. 머리줄을 쪽마다 다시 찍는다.
- **한계:** 굵은 글씨가 없다. 글꼴 하나만 쓰므로 그 글꼴에 없는 글자는 코드값으로 나온다.

## 지식DB 문서 검증 (2026-11-03, 독립 검증)

**2026-11-04 고침:** 아래 5건을 `deploy/htodb/ERD.md`·`API.md`에 반영하고 적재본 `htodb-94f8b6ff7f24`를 적었다. 숫자는 실제 DB에서 다시 셌다(쉼표 독성 87·물성 22, H229 `del_yn='Y'` 2건씩, CAS 중복 0, KE 중복 값 584·UN 289, UN 최대 2,135건). 부등호 문장 건수는 세는 기준에 따라 달라(독성 약 50~75, 문장 어디든 부등호가 있으면 75, 값 앞에 붙은 것만 51) 문서에는 "독성 수십 행, 물성 몇 행"으로 적었다.
