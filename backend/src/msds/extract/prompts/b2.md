# 이번 묶음: ② 8·9항
읽을 곳: 8항 노출방지 및 개인보호구(노출기준), 9항 물리화학적 특성
뽑을 칸: msds[].exposure_limits, msds[].physchem

## 묶음 안내
- 8항 노출기준(exposure_limits): 성분 × 기준 출처(국내·ACGIH 등) × 기준 종류(TWA·STEL·C)마다 한 행이다. TWA와 STEL을 한 행에 합치지 않는다. 값은 q(Q)로 나눈다.
- 생물학적 노출기준도 행으로 남긴다(standard="생물학적").
- 9항 물리화학적 특성(physchem): 특성마다 한 행(prop_code). 숫자 값은 q, 글자 값은 text_value. 괄호 속 측정 조건은 cond(COND)로 나눈다.
- 성분마다 값이 따로 적혀 있으면 [성분 목록]의 comp_ref로 구분하고, 제품 전체 값은 comp_ref="MIX"(R10).
- 특성 이름의 표기가 달라도 [동의어]로 코드를 정한다(R25).

## [필드 정의] (TO21 명세서 1_항목정의)
형식: `경로` 이름 — 타입, 중요도. 형식·분해 규칙 [참조] 예(가상 값)
- `exposure_limits[].comp_ref` 대상 성분 — string, 필수. 성분 seq 또는 'MIX' [참조 R10, V11] 예: 1 (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `exposure_limits[].standard` 기준 출처 — enum, 필수. 국내/ACGIH/OSHA/NIOSH/EU/생물학적/기타 [참조 C7] 예: 국내 (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `exposure_limits[].limit_type` 기준 종류 — enum, 필수. TWA / STEL / C / BEI / 기타 — 한 줄에 여러 개면 행을 나눔 예: TWA (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `exposure_limits[].q` 기준값 — Q, 필수. Q 구조 [참조 R04] (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `exposure_limits[].form` 입자 형태 — string, 일반. 원문 그대로(Thoracic particulate mass, 흡입성 등) — 번역하지 않음 [참조 R17] 예: Thoracic particulate mass
- `exposure_limits[].kr_basis` 국내 기준 구분 — enum, 중요. 노출기준 / 허용기준 (국내일 때) 예: 노출기준
- `exposure_limits[].bio_medium` 시료 매체 — string, 일반. 생물학적 노출기준: 혈액 / 소변 / 호기 등 예: 소변
- `exposure_limits[].bio_timing` 채취 시기 — string, 일반. 작업 종료 시 등 예: 작업 종료 시
- `exposure_limits[].bio_determinant` 지표 물질 — string, 일반. 예: 마뇨산
- `exposure_limits[].notations[]` 표기 — string, 일반. Skin, 발암성 1A, 생식독성 등 [참조 R11]
- `physchem[].prop_code` 특성 코드 — code, 필수. C4 [참조 C4] 예: FLASH_POINT (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `physchem[].comp_ref` 대상 성분 — string, 필수. 제품 값이면 'MIX' [참조 R10] 예: MIX (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `physchem[].q` 값 — Q, 필수. 숫자 특성은 Q, 외관·냄새는 text_value [참조 R04, R06, V12, V13] (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `physchem[].text_value` 텍스트 값 — string, 필수. 외관(액체), 색(무색) 등 (※ 행 단위 항목은 코드표의 중요도가 '필수'인 코드만 필수로 평가)
- `physchem[].cond` 측정 조건 — COND, 중요. 괄호·@ 뒤 조건을 분리
- `physchem[].seq` 순번 — integer, 중요. 같은 특성 값이 여러 개(pH 0.3(1N), 1.2(0.1N) 등)일 때 순서 예: 1
- `physchem[].data_source` 자료 출처 — string, 일반. 값 뒤에 붙은 출처(ECHA 등) 예: ECHA

## [규칙] (TO21 명세서 3_정규화규칙)
- R04 수치 분해(Q): 원문은 raw에 보존하고 부등호·값·단위를 각각 분리. '이상'=>=, '초과'=>, '이하'=<=, '미만'=<. 범위는 lower/upper, 단일값은 value. 원문 예: 20 ~ 30 % / <1 % / 99.92 / ≥ 95 / 10% 이상 / 1 미만 / 약 23 ℃ → 저장 예: {lower_op:'>=',lower:20,upper_op:'<=',upper:30,unit:'%'} / {upper_op:'<',upper:1,unit:'%'} / {value:99.92} / {lower_op:'>=',lower:95} / {lower_op:'>=',lower:10,unit:'%'} / {upper_op:'<',upper:1} / {value:23,approx:true,unit:'C'} ('~'로 묶인 범위의 양 끝은 포함(>=, <=)으로 간주)
- R06 숫자: 천단위 콤마 제거, 지수 표기 허용, '약'·'approx.'는 approx=true로. 원문 소수 자릿수는 dp에 기록(2.0 → value 2, dp 1). 원문 예: 약 1,000 / 1.2E-3 / 2.0 → 저장 예: 1000(approx) / 0.0012 / 2(dp=1) (MSDS 재생성 시 '2.0' 그대로 출력하기 위함)
- R08 단위: ㎥→m3, ℃→C, ㎎→mg 등 기호 통일. 단위 변환은 하지 않음(PoC 범위 밖). 원문 예: mg/㎥ / 23 ℃ → 저장 예: mg/m3 / 23 C
- R10 성분 참조(comp_ref): 8·11·12·15항 값이 특정 성분 것이면 components[].seq, 제품 전체면 'MIX'. CAS로 먼저 매칭, 없으면 이름. 원문 예: [황산] : TWA 0.2 mg/㎥ → 저장 예: comp_ref=1
- R11 목록 분리: 이명·동의어·용도는 ';' 또는 ',' 기준으로 배열 분리, 앞뒤 공백 제거. 단 괄호 안의 예시 목록은 쪼개지 않고 상위 항목과 함께 하나로 둠(정보 손실 방지). 원문 예: 메틸벤젠 ; 메틸벤졸 / 비료, 다양한 공정 보조제(pH조절제, 응집제 등) → 저장 예: ["메틸벤젠","메틸벤졸"] / ["비료","다양한 공정 보조제(pH조절제, 응집제 등)"]
- R15 자료없음/해당없음: 두 표기를 구분해 status에 저장(고시 제11조제7항). 빈칸·'-'는 미기재로 처리. 원문 예: 자료없음 / 해당 없음 / - → 저장 예: 자료없음 / 해당없음 / 미기재
- R17 원문 우선: 정규화로 의미가 바뀔 위험이 있으면 정규화하지 않고 raw만 채움. 추측 금지.
- R25 동의어 사전 적용: 항목 제목·규제 항목·물성 이름의 표기 변형은 동의어 사전(TO21_MSDS_동의어사전)으로 표준 코드에 매핑. 사전에 없는 변형은 extras로 보내고 사전 추가 요청. 원문 예: 증기비중 / 물리 · 화학적 성질 → 저장 예: VAPOR_DENSITY / 9항

## [공통 구조] 숫자(Q)·측정 조건(COND)·서술 문장(STMT) (TO21 명세서 2_공통구조)
모든 수치는 Q, 측정조건은 COND, 서술형 문장은 STMT로 저장. '택1' = value 또는 lower/upper 중 하나.

lower_op | 하한 부등호 | enum | 택1 | > 또는 >= ('이상'=>=, '초과'=>) | >=
