앱은 어떤 일을 하나요?

문서에서 값을 뽑아 저장하고 정답과 비교하는 순서를 설명합니다.

AI는 안전 문서의 내용을 정해진 칸으로 옮깁니다.

  1. PDF에서 쪽별 글자를 읽습니다.
  2. 문서를 16개 부분으로 나눕니다.
  3. AI가 필요한 값을 뽑습니다.
  4. 정해진 결과 형식(JSON)으로 저장합니다.
  5. 답안과 비교해 점수를 매깁니다.

이 화면은 그 결과를 검토하는 사람을 위한 도구입니다.

실행 폴더 이름은 날짜와 모델 설정과 지시문 버전과 입력 자료와 회차를 이어 쓴 기록입니다.

예: s8은 AI에게 시킬 일의 8번째 판입니다. _r2는 같은 조건의 두 번째 시험입니다.

실행 조건을 펼치면 원래 폴더 이름과 각 조건을 확인할 수 있습니다. 없는 기록은 추정하지 않습니다.

첫 사용 안내는 결과 읽기와 한 부분 실제 시험의 두 갈래입니다. 다시 보기는 성공 기록과 연습 기록을 지우지 않습니다.

가장 큰 문제의 값과 실제 근거 줄을 함께 열면 결과 읽기를 마칩니다. 근거가 없으면 임의의 줄로 대신하지 않습니다.

실제 시험의 해석이 성공한 결과 요약을 열면 실제 성공을 기록합니다. 입력 확인 연습은 따로 기록합니다.

안내 기록은 runs/manual/journey.json에 보관합니다. 저장이 실패해도 다른 기능은 쓸 수 있습니다.

카드 접힘은 브라우저에 보관합니다. 저장소를 쓸 수 없어도 화면은 사용할 수 있습니다.

점수와 문제 건수는 어떻게 읽나요?

두 목표와 정답의 신뢰 범위를 구분합니다.

중요한 항목에는 더 큰 비중을 줍니다.

전체 목표 점수은 90점입니다.

필수 17개 항목의 목표 달성 수는 따로 확인합니다.

필수 17개는 각각 무게 3입니다. 중요 4개는 각각 무게 2입니다. 일반 2개는 각각 무게 1입니다.

각 기준의 목표는 점수 계산 기준에서 확인합니다. 필수는 대부분 95%입니다. 유해성 분류와 급성독성은 90%입니다.

전체 점수와 필수 기준의 목표 달성 수를 따로 읽습니다. 목표 달성은 제품의 안전 판정이 아닙니다.

정답도 틀릴 수 있습니다.

점수는 모델과 지시문을 비교하는 참고값입니다. 원문에서 맞는 값을 확인하세요.

값 없는 행은 자료없음·해당없음·비해당·미기재처럼 상태만 적힌 줄입니다. 표기 규칙은 정답 담당자가 정합니다.

보조 점수는 정답과 AI 결과 양쪽에서 값 없는 행을 뺀 뒤 계산합니다. 차이가 크면 그 행의 표기를 확인하세요.

정답지 주의에는 빈칸과 출처가 표시됩니다. 값 없는 노출기준 행의 기준 종류도 확인 대상입니다.

이전 정답 초안의 검토 기록에서는 값 없는 독성 행 232개 중 209개의 숫자 칸이 비었습니다. 현재 정답지에도 같은 문제가 있다고 단정하지 않습니다.

문제 건수는 그 기준에서 찾은 문제 값의 수입니다. 건수만으로 손실 점수를 계산하지 않습니다.

2점 이상 하락한 항목의 원인 후보는 추정입니다.

  1. 조건: 모델과 지시문과 입력 자료와 동시 요청 수가 달라졌는지 봅니다.
  2. 요청: 두 번째 결과에서만 실패나 길이 제한이나 재추출이 생겼는지 봅니다.
  3. 문제 종류: 못 뽑음과 만듦과 틀림의 건수가 늘었는지 봅니다.
  4. 문서: 점수가 가장 많이 내려간 문서를 최대 세 건 봅니다.
  5. 표: 정답과의 행 수 차이가 5% 또는 1행 이상 더 커졌는지 봅니다.
  6. 흔들림: 조건이 같으면 반복 실행의 차이일 수 있습니다. 원인은 원문에서 확인합니다.

문제 값을 원문에서 어떻게 확인하나요?

실제 근거 줄과 추정 줄을 구분해 읽습니다.

AI가 채운 값과 같은 위치의 원문 줄을 비교합니다.

값을 누르면 근거 줄이 선택됩니다. 줄을 누르면 그 줄을 근거로 쓴 값이 선택됩니다.

예: 2쪽 23번째 줄에는 5 mg/m³가 적혀 있습니다.

근거가 없으면 임의의 줄을 대신 선택하지 않습니다.

못 뽑은 값의 위치는 글자를 맞춰 추정합니다. 추정 줄만 열어서는 결과 읽기 안내를 완료하지 않습니다.

같음과 다름과 정답에만 있음은 글로 구분합니다. 지금 고른 값과 줄은 노란 바탕으로 표시합니다.

원문 자료와 정답은 무엇이고 어떻게 바꾸나요?

AI가 읽는 글과 점수 기준의 뜻, 바꾸고 새로 더하는 순서를 설명합니다.

원문 자료(문서 묶음)는 PDF를 쪽마다 글자와 그림으로 바꿔 둔 파일입니다. AI는 이 글자를 읽고, 근거도 이 글자의 줄 번호로 댑니다.

예: p5:L22는 5쪽 22번째 줄입니다.

바꾸기: 화면 위 ‘필요할 때 문서 바꾸기’에서 다른 묶음을 고릅니다. 그 묶음으로 돌린 저장 결과만 보입니다.

원문 자료를 새로 더하는 순서입니다.

  1. data/pages/<묶음 이름>/<문서 번호>/ 폴더를 만듭니다.
  2. 쪽마다 p001.txt(글자)와 p001.png(그림)를 넣습니다. 글자 줄 앞에 L001 같은 줄 번호가 있어야 새 시험에 쓸 수 있습니다.
  3. data/manifest.csv에 없는 문서 번호라면 meta.json도 넣습니다. 안의 doc_id가 폴더 이름과 같아야 열립니다.
  4. 화면을 새로고침하면 목록에 나타납니다. 앱을 다시 켤 필요는 없습니다.

평가용 문서는 점수가 부풀려지지 않도록 개발 중에는 열지 않습니다. 목록에 잠김으로 보입니다. data/pages는 git에 올리지 않습니다.

정답은 AI 값과 견주는 기준입니다. 점수는 AI가 뽑은 값이 정답과 얼마나 같은지로 계산합니다. 정답을 바꾸면 같은 결과의 점수도 달라집니다.

  • 사람이 확인한 정답(골드)은 사람이 검토해 확정한 답입니다. data/gold에 있습니다.
  • AI 정답 초안(실버)은 AI가 먼저 만든 비교용 답입니다. data/silver 아래 폴더에 있고, 틀릴 수 있습니다.

바꾸기: 화면 위 ‘필요할 때 정답 바꾸기’에서 고릅니다. 저장된 결과를 AI 없이 다시 채점합니다.

정답을 새로 더하는 순서입니다.

  1. data/silver/<이름>/ 또는 data/gold/<이름>/ 폴더를 만듭니다.
  2. 문서마다 <문서 번호>.json을 넣습니다. 예: T21-S001.json. 정해진 결과 형식(TO21 JSON)이어야 합니다.
  3. 화면을 새로고침하면 목록에 나타납니다. 앱을 다시 켤 필요는 없습니다.

골드는 A 담당이 검수해 올립니다. 고칠 곳을 찾으면 파일을 직접 바꾸지 말고 A 담당에게 알립니다. 평가용 문서의 정답은 열지 않고 개수만 셉니다.

실제 시험 전에 무엇을 준비하나요?

저장 결과 읽기와 모델 접속 설정을 구분합니다.

저장 결과를 읽는 데는 서버 설정이 필요 없습니다.

실제 시험에 쓸 설정은 프로젝트의 .env 파일에서 준비합니다.

아래는 설정 이름뿐입니다.

설정 이름뜻
RUNPOD_VLLM_BASE_URL빌린 서버의 중계 주소(RunPod 프록시). SSH 연결 주소가 아닙니다.
RUNPOD_VLLM_API_KEY빌린 서버의 모델 접속 키
RNGD_BASE_URL회사 모델에 요청을 보내는 내 컴퓨터 쪽 주소
RNGD_API_KEY회사 모델의 접속 키
RUNPOD_API_KEY빌린 서버를 만들고 삭제할 때 쓰는 관리 키
RNGD_SSH회사 서버에 접속하는 보안 연결(SSH) 설정

RUNPOD_VLLM_BASE_URL은 빌린 서버의 중계 주소입니다. SSH 연결 주소가 아닙니다.

회사 서버는 보안 연결 통로(SSH 터널)를 사용합니다. RNGD_SSH에서 접속 옵션을 준비합니다.

프로젝트 최상위의 .env.example을 복사한 파일 이름을 .env로 바꿉니다. .env는 Git에 올리지 않습니다.

비밀값은 화면이나 기록에 넣지 않습니다.

앱 시작 명령:

(cd backend && .venv/bin/python scripts/b_app.py)

프로젝트 최상위에서 앱을 켭니다. 내 컴퓨터 127.0.0.1에서만 열립니다. 터미널에 표시된 주소를 브라우저에 입력하세요.

설정을 고친 뒤 AI 켜기와 비용에서 설정 다시 읽기를 누르세요.

한 부분을 어떻게 다시 시험하나요?

AI 없이 확인하는 연습과 실제 시험을 구분합니다.

문서의 같은 부분을 다시 보내 수정 효과를 확인합니다.

  1. 다시 시험에서 개발용 문서와 문서 부분과 모델을 고릅니다. 여러 부분이나 문서 전체도 시험할 수 있습니다.
  2. 모델 준비 상태를 확인하세요. 연결된 모델이 없으면 AI 켜기와 비용에서 준비합니다.
  3. 입력 확인 연습은 AI를 부르지 않습니다. 보낼 입력과 지시문만 확인합니다.
  4. 실제 시험 시작을 누른 뒤 결과 요약을 엽니다. 여섯 단계를 차례로 펼쳐 보세요.
진행내용
1. 보낸 입력AI에게 보낸 원문 글자입니다. 앞에 붙은 p2:L23은 2쪽 23번째 줄입니다.
2. AI에게 시킨 일 기록AI에게 시킨 일입니다. 글 전체를 기록 파일에 남기지 않습니다.
3. AI의 원래 답AI가 쓴 답을 그대로 보여 줍니다.
4. 읽어 낸 값AI의 답에서 읽어 낸 값입니다. 표로 읽지 못해 버린 줄 수도 보입니다.
5. 정해진 형식으로 바꾼 값읽어 낸 값을 정해진 결과 칸(TO21 JSON)에 넣은 내용입니다.
6. 시험 전후 점수이전 결과에서 시험한 부분의 답만 바꿔 다시 계산한 점수입니다. 전체를 새로 시험한 점수는 아닙니다.

여러 문서 시험에서 개발용 문서와 반복 횟수를 고릅니다. 두 결과 비교에서는 여러 결과의 비교표도 만들 수 있습니다.

작업 기록에서 진행과 오류를 봅니다. 중단이 허용된 작업만 멈출 수 있습니다.
