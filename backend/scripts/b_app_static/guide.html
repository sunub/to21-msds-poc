B 작업 화면 도움말

이 문서는 작업 화면을 처음 켜는 사람을 위한 안내서입니다. 절은 아홉 개이고 위에서부터 차례로 읽으면 됩니다.

1 무엇을 하나2 점수3 탭4 준비5 시험6 안내문7 실패8 금지9 용어

이 도구는 무엇을 하나

이 도구는 안전보건자료(MSDS, 화학물질 안전 정보를 적은 문서) 한 장에서 정보를 뽑는 과정을 보여 주고 다룹니다.

MSDS는 법으로 정해진 16개 항목으로 되어 있습니다. 도구는 이 16개를 각각 따로 모델에 보냅니다.

받은 답을 모아 정해진 틀의 결과 파일(JSON)을 만듭니다. 그 결과를 정답 초안(실버)과 비교해 점수를 냅니다.

이 화면의 일은 두 가지입니다.

  • 실행 결과의 점수와 문제를 눈으로 확인합니다.
  • 항 하나만 다시 보내 고쳐 본 뒤 점수가 어떻게 달라지는지 봅니다.

예: 실행 폴더 이름 20261030_sections_qwen36_35b_runpod_s7_v9_dev10_r1은 날짜, 모델 태그, 안내문 버전(s7), 입력 판(v9), 용도(dev10), 회차(r1)를 이어 쓴 것입니다.

점수는 어떻게 읽나

점수 기준은 화면의 "합격 기준" 카드에 나옵니다. 합격 규칙은 한 줄입니다.

예: 필수 17개가 모두 목표 이상이고 가중 종합 90점 이상

용어 두 개를 먼저 풉니다.

  • 가중 종합: 항목 23개의 점수를 무게를 곱해 평균 낸 값입니다. 필수는 3, 중요는 2, 일반은 1을 곱합니다.
  • 필수 통과: 필수 항목 17개가 각자 정한 목표를 넘은 개수입니다. 17/17이어야 합격입니다.

필수마다 목표가 다릅니다. 대부분 0.95이고 유해성 분류와 11항 급성독성은 0.9입니다. 가중 종합이 90점이어도 필수 하나가 모자라면 불합격입니다.

점수가 두 개 보이는 이유

"값 없는 행을 뺀 점수"가 지금 점수 옆에 한 줄 더 있습니다.

값 없는 행은 원문에 "자료없음", "해당없음", "비해당", "미기재"라고만 적힌 행입니다. 이런 행의 표기 규칙은 아직 A 담당이 정리하는 중입니다.

그래서 두 점수를 같이 봅니다. 한 점수는 표기 차이까지 포함하고, 다른 점수는 표기 차이를 걷어 낸 값입니다. 두 점수의 차이가 크면 모델이 아니라 값 없는 행 표기 때문에 깎인 것입니다.

예: 항목 이름 옆 주황 점(●)에 마우스를 올리면 실버 빈 곳이 나옵니다. 8항 노출기준은 "값 없는 노출기준 행의 기준 종류(TWA·BEI)는 A의 표기 규칙 함수가 기본값으로 채운 것이다"라고 적혀 있습니다.

"정답은 실버라 순위 비교용"의 뜻

지금 정답은 진짜 정답(골드)이 아니라 Claude가 먼저 뽑은 초안(실버)입니다. 실버도 틀릴 수 있습니다.

그래서 점수는 모델끼리, 안내문 버전끼리 순위를 매길 때만 믿습니다. 점수 하나로 합격을 선언하지 않습니다.

예: 실버가 값 없는 독성 행 232개 중 209개의 q를 비워 둔다는 기록이 있습니다. 이때는 우리 결과가 맞고 실버가 어긋날 수 있습니다.

탭마다 무엇을 보나

① 점수판

실행 하나의 지금 점수, 합격 기준, 항목 23개의 신호등을 봅니다. 항목을 펼치면 틀린 값이 나옵니다.

아래에는 실행 역사, 문서별 점수와 시간, 호출 격자, 표 행 수가 있습니다. 호출 격자는 칸 하나가 모델 호출 하나입니다.

② 두 실행 비교

두 실행을 골라 점수 차와 바뀐 값을 봅니다. 점수가 내려간 항목에는 "왜?" 단추가 붙습니다.

"하락 원인"은 아래 여섯 규칙을 이 순서대로 검사해 근거가 있는 것만 문장으로 적습니다.

  1. 조건: 안내문, 모델, 입력 판, 동시 호출 수가 바뀌었는가
  2. 호출: B에서만 실패하거나 출력 한도에 걸리거나 재추출한 호출이 있는가
  3. 종류: 빠뜨림·지어냄·틀림 개수가 늘었는가
  4. 문서: 어느 문서가 가장 많이 내려갔는가(위 세 개)
  5. 행 수: 결과 행 수가 정답에서 5% 또는 1행 이상 더 멀어졌는가
  6. 흔들림: 조건이 모두 같으면 모델 흔들림일 수 있다고 적는다
예: 조건이 같을 때 문장은 "조건이 같으므로 모델 흔들림일 수 있다(동시 16개 호출, ADR-014)" 모양입니다.

이 문장은 원인의 후보입니다. 확정이 아니므로 마지막은 ③ 원문 대조에서 눈으로 확인합니다.

③ 원문 대조

쪽 그림, 줄 글자, 결과 값, 실버를 나란히 봅니다. 값을 누르면 원문 줄이 켜지고 줄을 누르면 그 줄을 근거로 쓴 값이 켜집니다.

색은 세 가지입니다. 회색은 실버와 같음, 주황은 실버와 다르거나 실버에 없음, 빨강은 문제 있는 곳입니다.

④ 작업

칸이 세 개입니다.

  • 시험하기: 항 하나나 문서 하나를 모델에 보내 단계별로 봅니다.
  • 본 실행: 개발용 문서 여러 건을 여러 회 돌립니다.
  • 비교표: 끝난 실행들을 한 표로 묶습니다.

아래 작업 목록에서 로그를 보고 돌고 있는 작업을 멈출 수 있습니다.

⑤ 서버

지금 연결된 모델을 보여 줍니다. RunPod Pod 만들기·지우기와 RNGD 모델 올리기·내리기도 여기서 합니다.

바꾸는 단추는 모두 두 단계입니다. 누르면 요약 창이 뜨고, 거기서 "확인"을 눌러야 실행됩니다. 실행이나 시험이 돌고 있으면 단추가 잠깁니다.

저장소 최상위의 .env 파일에 변수 여섯 개를 적어 둡니다. 이 문서에는 이름만 적습니다. 값과 주소는 적지 않습니다.

켜면 내 컴퓨터(127.0.0.1)에서만 열립니다. 켠 터미널에 찍히는 주소를 브라우저에 입력합니다.

시험 하나 돌리기

시험은 항 하나만 모델에 보내 보는 가장 작은 실험입니다. 순서는 네 단계입니다.

  1. ⑤ 서버 탭에서 쓸 모델이 "연결됨"인지 봅니다. 아니면 먼저 올립니다.
  2. ④ 작업 탭의 "시험하기"에서 모델, 개발용 문서, 항을 고릅니다.
  3. 단추(안내문 보기만이면 "입력·안내문 보기", 아니면 "돌리기")를 누릅니다. "dry-run (서버 없이 입력·안내문만)"을 켜면 서버 없이 보낼 내용만 봅니다.
  4. 결과의 여섯 단계를 위에서부터 읽습니다.
단계무엇을 보나
① 보낸 입력모델에게 준 줄 글자. 줄 번호(p2:L23 모양)가 앞에 붙어 있습니다.
② 안내문모델에게 준 지시문. 화면에만 보이고 파일로 저장하지 않습니다.
③ 모델 원문 답모델이 쓴 글 그대로입니다.
④ 읽은 결과원문 답을 중간 형식으로 바꾼 것. 행 형식에서 버린 줄 수도 나옵니다.
⑤ 펼친 TO21 칸중간 형식을 최종 JSON 칸으로 펼친 것입니다.
⑥ 점수 전 → 후기준 실행의 해당 항 답을 새 답으로 바꿔 끼워 다시 채점한 점수입니다.

같은 일을 터미널에서도 할 수 있습니다. 항 번호와 모델 태그는 try_section.py --help가 알려 줍니다.

(cd backend && .venv/bin/python scripts/try_section.py --model <태그> --doc <문서 번호> --section 11 --dry-run)

옵션은 아래 일곱 가지를 주로 씁니다.

  • --section: 항 번호. 여러 번 줄 수 있습니다.
  • --all: 문서 전체(16개 항)를 실행기로 돌립니다.
  • --dry-run: 보낸 입력과 안내문만 보이고 서버를 부르지 않습니다.
  • --system-file: 이 글을 안내문 대신 보냅니다. --section 하나일 때만 됩니다.
  • --base-run: 끼워 넣을 기준 실행 이름입니다.
  • --show-prompt: 안내문 전문을 찍습니다. 화면에만 나옵니다.
  • --json: 같은 내용을 JSON 한 덩이로 찍습니다.
예: --doc는 "평가용 문서는 받지 않는다 (D-43)"고 도움말에 적혀 있습니다.

안내문을 바꿔 보기

안내문은 모델에게 주는 지시문입니다. 항마다 하나씩 있고, 실행할 때마다 코드가 새로 만듭니다.

세 곳에서 옵니다.

  • 명세서(TO21 v0.6)에서 꺼낸 칸 정의와 규칙
  • section_prompts.py의 공통 지시와 항마다 붙는 안내
  • 표 항목(행 형식)은 rows.py의 rows_guide가 만든 응답 형식 안내

안내문은 명세서 내용을 담고 있어서 파일로 저장하지 않습니다. 바꿔 보는 순서는 아래와 같습니다.

  1. ④ 작업 탭에서 항 하나를 고르고 "항의 지금 안내문 불러오기"로 글상자를 채웁니다.
  2. 글상자의 글을 고친 뒤 돌립니다. ⑥ 점수 전 → 후로 효과를 봅니다.
  3. 좋아졌으면 같은 수정을 section_prompts.py나 rows.py에 직접 반영합니다.
  4. 안내문 버전(SECTION_PROMPT_VERSION)을 올리고 본 실행으로 개발용 문서 전체를 확인합니다.

글상자 내용은 저장되지 않습니다. 화면을 닫거나 새로고침하면 사라지므로 마음에 드는 글은 코드에 바로 옮깁니다. 기록에는 해시(글의 지문)만 남습니다.

효과는 한 번의 시험으로 확정하지 않습니다. 모델은 같은 입력에도 조금씩 다르게 답합니다(흔들림). 본 실행을 여러 회 돌려 평균으로 판단합니다.

자주 보는 실패 네 가지

1. 출력 한도

증상: 호출 격자 칸에 "긴출력", "공백폭주", "반복" 중 하나가 적히고 주황색으로 보입니다. 실패하면 칸이 빨갛고 ✕가 적힙니다.

어디서 보나: ① 점수판의 호출 격자. 칸에 마우스를 올리면 시도 횟수와 시간이 나옵니다.

보통 원인: 모델 답이 출력 한도에서 잘렸습니다(finish_reason=length). 이유는 세 가지로 나뉩니다.

  • 긴출력: 답이 정말 길었습니다. 표 행이 아주 많은 문서에서 나옵니다.
  • 공백폭주: 답의 절반 넘게 공백입니다. JSON 문법 강제와 함께 나타납니다.
  • 반복: 같은 말을 되풀이했습니다.

2. 열 수 불일치

증상: 시험 결과 ④ 읽은 결과의 "버린 줄" 숫자가 0이 아닙니다.

어디서 보나: 시험하기의 ④ 단계와 ③ 모델 원문 답.

보통 원인: 행 형식은 한 줄이 한 행이고 열 수가 정해져 있습니다. 모델이 칸 하나를 빼먹거나 더 쓰면 그 줄을 버립니다.

3. 5분 초과

증상: 문서 시간 막대가 300초 선을 넘습니다.

어디서 보나: ① 점수판의 "문서별 점수와 시간".

보통 원인: 한도에 걸린 호출을 한 번 더 보내서 시간이 두 배로 듭니다. 가장 긴 항 하나가 문서 시간을 정합니다.

4. 연결 오류

증상: 호출이 바로 실패하거나, 서버 탭에 모델이 연결 안 됨으로 나옵니다.

어디서 보나: ⑤ 서버 탭과 ④ 작업 탭의 작업 로그.

보통 원인: SSH 터널이 끊겼거나 Pod가 꺼졌거나, 컴퓨터가 잠자기에 들어갔습니다. 실행이 길면 잠자기 방지로 켜 둡니다.

하지 말 것

아래 다섯 가지는 하지 않습니다.

  • 평가용 문서 10건을 돌리지 않습니다(D-43). 점수가 부풀려져 진짜 평가가 의미를 잃습니다. 도구도 평가용 문서는 거부합니다.
  • 키를 어디에도 적지 않습니다. 파일, 로그, 시험, 채팅 모두 안 됩니다. 저장소와 실행 기록은 팀이 같이 봅니다.
  • 하네스(자동 실행기)가 돌 때 docs/를 고치지 않습니다. 보호 파일이 바뀌면 돌고 있던 단계가 실패합니다.
  • 쓰고 나서 Pod를 끄지 않고 두지 않습니다. 켜 둔 시간만큼 요금이 나갑니다. 서버 탭에서 지웁니다.
  • 시험을 돌릴 때 tests/test_preprocess.py를 함께 돌리지 않습니다. 이 시험이 실제 쪽 글자 폴더를 옛 방식 결과로 덮어씁니다. 항상 --ignore=tests/test_preprocess.py를 붙입니다.
(cd backend && .venv/bin/python -m pytest -q --ignore=tests/test_preprocess.py)
