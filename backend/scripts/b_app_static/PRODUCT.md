# 이 앱은 AI가 안전 문서에서 뽑은 값을 원문과 맞춰 보고 다시 시험하는 도구입니다.

## Product

제품 이름은 ‘화학 안전문서 AI 결과 검토’입니다.
화학물질 안전보건자료(MSDS)는 화학제품의 안전 정보를 담은 16개 부분짜리 문서입니다.
AI는 이 문서에서 값을 뽑아 정해진 결과 형식(TO21 JSON)에 채웁니다.
이 앱은 저장된 결과를 정답지와 비교합니다.
개발용 작업 화면을 전면 재설계하는 결정(ADR-028)을 따릅니다.
이 문서는 기존 PRODUCT.md를 교체할 새 정본입니다.
현재 제품 파일은 변경하지 않았습니다.

## Users and Context

사용자는 프로젝트 지식과 사용 빈도가 다릅니다.

- 처음 온 사람: 개발 경험이 조금 있지만 프로젝트는 모릅니다. 별도 설명 없이 점수의 뜻과 다음 행동을 찾아야 합니다.
- 담당자 B: 모델의 설명을 고쳐 반복 시험합니다. 입력 조건과 결과를 자주 비교합니다.
- 동료 A: 정답과 채점 기준을 확인합니다. 서버 없이 저장 결과를 읽을 수 있어야 합니다.
- 동료 C: 원문의 글자와 근거 위치를 확인합니다. 서버 없이 원문 대조를 할 수 있어야 합니다.

## Jobs

사용자가 끝내려는 일은 승인 구조의 다섯 가지입니다.

1. 최근 점수와 총점 손실이 가장 큰 문제를 이해합니다.
2. 문제 값을 원문 줄과 맞춰 봅니다.
3. 같은 문서의 같은 부분을 다시 시험합니다.
4. 여러 문서를 실행하고 실행끼리 비교합니다.
5. 필요한 모델을 연결하고 서버의 시간과 비용을 관리합니다.

## First Success

두 갈래는 서로 독립입니다.
서버 없이 시작할 수 있는 갈래 1을 먼저 권합니다.
재방문은 최근 결과 요약으로 시작합니다.

| 갈래 | 정확한 성공 조건 | 성공이 아닌 경우 |
|---|---|---|
| 1. 점수에서 원문까지 | S01의 가장 큰 문제에서 S02로 진입합니다. 선택 값의 `items`에 그 채점 기준이 있습니다. 해당 항의 `values[]` 값이 정답과 다릅니다. 그 값의 `lines[]`에 실제 존재하는 줄이 있습니다. 값과 줄이 보이는 S02에서 함께 선택됩니다. | 단추만 누름, 같은 값, 다른 기준의 값, 근거 없음, 줄 읽기 실패. `silver_only[].lines`의 추정 줄만 확인한 경우도 기존 성공 조건을 충족하지 않습니다. |
| 2. 한 부분 실제 시험 | 앱의 한 부분 시험 작업입니다. `status=done`, `returncode=0`, `dry_run=false`입니다. 결과 요청이 200입니다. `results["8"].ok=true`처럼 선택 항의 해석이 성공합니다. `plan.doc_id`와 `plan.sections`가 보낸 대상과 같습니다. 취소하지 않은 시도의 결과 요약을 사용자가 엽니다. | 연습, 작업 실패, `ok=false`, 결과 없음 204, 대상 불일치, 취소, 실제 호출 여부 미확인, 다른 터미널 작업. 문서 전체 시험은 한 부분 안내의 성공으로 대신 세지 않습니다. |

예: `results["8"].ok=false`인 장면에는 ‘실제 시험 성공은 기록하지 않았습니다’가 보입니다.
전후 점수는 갈래 2 성공의 필수 조건이 아닙니다.
정답이 없으면 점수를 생략한 이유를 보여 줍니다.
입력 확인 연습(dry-run)은 모델을 부르지 않습니다.
연습 결과에는 `plan`만 있습니다.
연습 완료는 `outcomes.t2.practice`에만 기록합니다.
연습은 갈래 2의 실제 성공이나 진행 단계를 올리지 않습니다.
같은 작업의 결과를 다시 열어도 성공 횟수를 더하지 않습니다.

## Product Truth

정답 초안은 AI가 먼저 만든 답입니다.
사람이 확인한 정답(골드)은 일부 개발 문서에만 있습니다.
사람 확인 전 점수는 참고값입니다.
정답 종류와 채점 문서 수를 점수 가까이 표시합니다.
현재 정답지의 내용 지문(`fingerprint`)은 과거 정답지를 재현한다는 뜻이 아닙니다.

점수에는 두 목표가 있습니다.

- 전체 점수의 목표선은 90점입니다.
- 꼭 맞춰야 하는 기준 17가지의 목표 달성 수를 따로 표시합니다.

점수는 23가지 기준의 중요도를 반영합니다.
필수 17개의 무게는 각각 3입니다.
중요 4개의 무게는 각각 2입니다.
일반 2개의 무게는 각각 1입니다.
무게 합은 61입니다.
가장 큰 문제는 `/api/run`의 `status_text.top_problem`을 따릅니다.
손실 순서는 `losses`의 서버 순서를 사용합니다.
목표를 넘은 기준의 손실도 포함합니다.
예: 시안의 허용 농도 손실은 `3 × (1 − 0.40) ÷ 61 × 100 ≈ 2.95점`입니다.

문서 묶음을 바꾸면 해당 묶음의 결과를 찾습니다.
결과가 없으면 ‘결과 없음’을 보입니다.
정답지를 바꾸면 저장된 결과를 다시 채점합니다.
이때 AI를 다시 호출하지 않습니다.
과거 원문은 실행 당시 묶음으로 엽니다.
다음 시험의 묶음과 다르면 두 조건을 구분합니다.

## Server Facts

| 방법 | 추가 임대료 | 준비 | 사용 뒤 |
|---|---|---|---|
| 회사 서버(RNGD) | 없음. 회사 운영 비용과는 별개입니다. | 보통 15~25분입니다. 한 번에 모델 하나만 올립니다. | 모델 내리기와 연결 닫기를 구분합니다. |
| 빌린 서버(RunPod) | 시간당 요금입니다. 시안의 약 $2.49는 예시입니다. | 준비 시간은 미확인일 수 있습니다. 4분은 경과 예시입니다. | 사용 뒤 삭제합니다. 앱이 만든 서버는 생성 후 4시간 자동 삭제 대상입니다. 앱이 켜져 있어야 예약을 확인합니다. |

이미 연결된 모델을 먼저 사용합니다.
연결된 모델이 없으면 회사 서버를 먼저 제시합니다.
다른 방법은 접힌 영역에 둡니다.
기존 임대 서버는 계약의 자동 인계를 사용합니다.
임의 서버를 골라 인계하는 기능은 만들지 않습니다.
서버 생성과 삭제는 확인을 거칩니다.
모델 올리기와 내리기도 확인을 거칩니다.
연결 통로 변경은 확인을 거칩니다.
앱이 만들지 않은 서버에는 삭제 행동이 없습니다.
모델 없음과 연결 통로 닫힘은 별개입니다.
상태 조회 실패를 모델 없음으로 표시하지 않습니다.

## Journey and Continuity

첫 사용 기록은 `runs/manual/journey.json`에 보관합니다.
읽기와 저장은 `GET /api/journey`와 `PUT /api/journey`를 씁니다.
기록은 안내 진행(`progress`)과 사용 결과(`outcomes`)를 구분합니다.
판정 대기 작업은 `pending`에 둡니다.
다시 보기와 건너뛰기는 성공 기록을 지우지 않습니다.
서버는 성공 횟수를 줄이지 않고 합칩니다.
새로고침 뒤에는 작업 번호로 기존 작업을 찾습니다.
보냈는지 모르면 자동으로 다시 보내지 않습니다.
저장 실패 때도 안내와 시험을 사용할 수 있습니다.
저장 실패 알림은 한 번 보입니다.
다음 상태 변화 때 다시 저장합니다.
진행 중 대상 변경은 작업을 안내에서 분리합니다.
작업 자체를 멈추지는 않습니다.
취소한 시도의 늦은 응답은 성공으로 세지 않습니다.
기록에는 원문과 지시문과 비밀값을 넣지 않습니다.

## Tone and Constraints

결론을 먼저 씁니다.
한 문장에는 사실 하나를 씁니다.
쉬운 말을 먼저 쓰고 원래 용어를 괄호에 둡니다.
모르는 상태는 ‘확인 안 됨’으로 씁니다.
실패는 확인한 사실과 복구 행동을 함께 보여 줍니다.

제품 경계는 다음과 같습니다.

- 데스크톱 폭 1280~1680px를 지원합니다. 가로 스크롤은 만들지 않습니다.
- 앱은 내 컴퓨터 주소 `127.0.0.1`에서만 엽니다.
- 외부 주소와 외부 글꼴과 CDN은 사용하지 않습니다.
- 새 패키지와 빌드 단계는 추가하지 않습니다.
- 평가용 문서 10건은 모든 경로에서 잠급니다. 목록에는 이유만 남깁니다.
- 시험 가능 여부는 문서별 `runnable`과 `run_reason`을 따릅니다.
- 비밀값은 화면과 로그에 출력하지 않습니다.
- 원문을 전처리하거나 평가 규칙을 바꾸는 기능은 이번 범위가 아닙니다.

## Evidence and Scope

정본 근거는 승인된 STRUCTURE.md와 plain-3입니다.
데이터 경계는 ARCHITECTURE.md의 ADR-028 API 표입니다.
이번 산출물은 가짜 자료로 만든 화면 시안입니다.
입력 편집은 실제 요청이나 저장으로 이어지지 않습니다.
실제 앱에는 디자인 확인용 예시 문구가 없습니다.
브라우저 검증과 새 사용자 8/10 평가는 이번 작업에서 실행하지 않았습니다.
