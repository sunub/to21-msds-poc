TO21 지식DB(HTODB) ERD

로컬 PostgreSQL(deploy/htodb/README.md로 적재)에 들어 있는 두 스키마의 구조입니다.

  • htodb: TO21이 준 HTODB 원본 16개 테이블과 적재 기록. 원본 SQL Server에서 이름만 소문자로 바꿔 그대로 옮겼습니다.
  • htodb_map: 명세서 v0.6의 13_TO21DB매핑 시트(추출 코드 ↔ HTODB 코드 번역표)와 적재 기록.

조회 API가 이 테이블을 어떻게 읽는지는 API.md에 있습니다.

행 수와 코드 종류는 2026-11-01 로컬 적재본 기준이고, 다시 적재하면 바뀔 수 있습니다. 데이터 값은 적지 않습니다(D-47).

#읽는 법

  • FK 제약이 없습니다. 관계선과 FK 표시는 조회 코드(repo.py)가 쓰는 조인을 적은 논리 관계입니다.
    • 실선: 짝이 모두 맞는 관계입니다.
    • 점선: 짝 없는 행이 조금 있는 관계입니다. 건수는 맨 아래 관계 목록에 있습니다.
  • _lang·_master 기준정보 테이블: PK에 lang_code 등이 들어 있지만 지금은 값이 하나뿐입니다(ko). 조인은 코드 컬럼만으로 합니다.
  • 생략한 컬럼: 모든 테이블에 반복되는 감사 컬럼(is_del/del_yn, init_*, update_*, tran_src)은 그림에서 뺐습니다.
  • 타입: 날짜와 숫자도 대부분 글자(varchar)입니다. NOT NULL은 PK 컬럼에만 있습니다.
  • 도구: Mermaid로 그렸습니다. GitHub와 PR에서 바로 그림으로 보이고, 외부 서비스에 구조를 올리지 않아도 됩니다. 복합 키는 선 이름에 +로 적었습니다.

#전체 관계도

컬럼을 뺀 그림입니다. 스키마는 모두 htodb입니다. 번역표(htodb_map)와의 관계는 선이 겹쳐서 아래 ④에 따로 그렸습니다.

#영역별 상세

#① 물질 · GHS 분류

물질 하나(chem_id)에 분류 결과 여러 개가 붙습니다. 분류 결과 코드(class_result_code) 하나에 H코드가 1~2개(hcode_seq) 있고, H코드마다 신호어·그림문자(hcode_phrase)와 H문구(hcode_phrase_lang)가 있습니다.

  • tb_ghs_chem_class_map.h_code는 tb_ghs_hcode_phrase.h_code와 같은 값을 한 번 더 적은 칸입니다. 그런데 23행은 두 값이 다릅니다. API는 두 값을 모두 그대로 돌려줍니다.
  • H문구가 없는 H코드 행이 3개 있습니다(hcode_phrase 136행, hcode_phrase_lang 133행).

#② 독성 · 물성

  • 값은 대부분 primary_value_text(원문 문장)에 있습니다. primary_value는 '=' 값일 때만 채워져 있고, 그것도 글자입니다. API의 parsed=true가 문장에서 숫자를 뽑아 따로 붙입니다(API.md 참고).
  • experiment_div는 대부분 div_code의 앞 다섯 글자와 같지만 다른 행도 있습니다(27행). 같다고 가정하고 조인하지 마세요.

#③ 규제 · 노출기준

법(regulate_id) 아래 세부 항목(regulate_item_id)이 있고, 항목마다 고시(notice_seq)가 있습니다. 물질이 어떤 항목에 해당하는지는 regula_chem_map에 있고, 그 물질의 고시 수치·글·노출기준은 "고시 + 물질-항목 쌍"에 매달립니다.

  • regulate_item_id는 값만으로도 유일합니다. API 코드 사전도 regulate_item_id 하나로 찾습니다.
  • 고시 500개 중 345개에는 물질별 수치(reg_notice_std) 행이 없습니다. 고시만 있고 수치는 없는 경우가 흔합니다.
  • std·content·exposure의 chem_id는 chem_master_info와 직접 비교해도 됩니다(API는 chem_id로 바로 조회합니다). 짝 없는 행 수는 아래 관계 목록에 있습니다.

#④ 번역표 · 적재 기록

htodb_map.sheet13은 시트 행을 셀 값 그대로 담고 있어서, 열 c1~`c7의 뜻이 묶음(section)마다 다릅니다. 번역 코드(backend/src/msds/compliance/htodb/mapping.py의 Map13`)는 아래처럼 읽습니다.

묶음 추출 JSON 쪽 HTODB 쪽 연결되는 테이블
A 물질 키(CAS·KE·UN) 비교 규칙 코드(normalize_cas, normalize_un)로 구현. 행은 번역에 쓰지 않음

  • c1이 (로 시작하는 행은 자리표시라서 번역에서 뺍니다. 시트 행 자체는 DB에 남아 있습니다.
  • section이 비어 있는 행 2개는 첫 묶음 제목보다 위에 있는 행입니다.
  • htodb.load_log는 적재한 원본 테이블마다 한 행(16행)입니다. knowledge_version(htodb- + 원본 zip SHA-256 앞 12자리)은 모든 행이 같습니다.
  • htodb_map.load_log의 map_version은 map13- + 명세서 xlsx SHA-256 앞 12자리입니다.
  • 두 버전은 API 응답마다 함께 돌려줍니다. 어느 적재본으로 낸 결과인지 남길 때 씁니다.

HTODB 조회 API

TO21 지식DB를 읽기만 하는 API입니다. 추출한 코드·CAS 번호를 HTODB 원본과 맞대어 볼 때 씁니다. 테이블 구조는 ERD.md를 보세요.

cd backend && .venv/bin/uvicorn --app-dir src msds.api.htodb_app:app --port 8010   # http://127.0.0.1:8010

#공통 규칙

  • 응답 모양: /health를 빼면 모두 {"knowledge_version": "...", "map_version": "...", "data": ...}입니다. 두 버전은 어느 적재본으로 답했는지 나타내므로, 결과를 저장할 때 함께 남기세요.
  • 값: DB 원본 그대로입니다. 행에는 테이블의 모든 컬럼이 들어 있고, 숫자 컬럼(numeric)은 자릿수를 지키려고 문자열("1.000")로 옵니다.
  • 없는 것: 없는 물질은 404, 없는 코드는 200에 빈 결과입니다. 번역표에 대응이 없으면 []이고, 비슷한 코드를 골라 주지 않습니다.
  • 오류: {"detail": "..."} 형식입니다. 매개변수 형식 오류(필수 값 없음 등)는 detail이 목록으로 옵니다.

아래 예시 값은 지어낸 것입니다(D-47).

#물질

#GET /chemicals

cas, ke, un 중 하나만 줍니다. limit은 1~500이고 기본 50입니다.

  • CAS: 공백과 특수 하이픈만 정리해서 비교합니다.
  • UN: UN 접두어와 공백을 무시합니다. UN1203, un 1203, 1203은 같은 값입니다.
"data": {"total": 1, "rows": [{"chem_id": "C0000001", "cas_no": "0000-00-0", "chem_name_ko": "예시물질", "...": "..."}]}

total이 2 이상이면 CAS 하나에 물질이 여러 개 걸린 것입니다. 어느 물질인지는 호출하는 쪽에서 골라야 합니다.

오류: 키를 0개나 2개 이상 주면 422.

#GET /chemicals/{chem_id}

data는 물질 행 하나(객체)입니다. 없으면 404.

#GET /chemicals/{chem_id}/{part}

원본 행(rows)과, 그 행들이 쓰는 코드의 이름 사전(codes)을 따로 돌려줍니다.

part data
classifications rows(환경부·고용노동부 분류 모두), codes{class_result_code: {class_master, hcode_phrase, hcode_phrase_lang}}
toxicity rows, codes{div_code: [...]}, parsed(선택)
physical-properties rows, codes{property_id: [...]}, parsed(선택)
regulations rows(해당 규제 항목), notice_std(수치), notice_content(글), notices(고시), codes{regulate_item_id: {regulate_item, regulate}}
exposure-limits rows(MSDS 8항 노출기준)

?parsed=true는 toxicity와 physical-properties에만 쓸 수 있습니다. 원본 문장에서 뽑은 숫자를 rows와 같은 순서의 parsed 목록으로 덧붙입니다(맨 아래 parsed 참고).

오류:

  • 모르는 part: 404
  • 다른 part에 parsed=true: 422 (물질이 없어도 이 검사가 먼저입니다)
  • 없는 물질: 404

#코드 이름 찾기 GET /codes/{종류}/{code}

종류 code 예 data
ghs-class 분류 결과 코드 {class_master, hcode_phrase, hcode_phrase_lang}: 분류 이름, H코드·신호어·그림문자, H문구
h H302 {hcode_phrase, hcode_phrase_lang, class_master}: 이 H코드를 쓰는 분류 전부
div GHS0201 독성 구분 행 목록
property G0907000000 물성 항목 행 목록
regulate-item 규제 항목 ID {regulate_item, regulate}: 항목 이름과 그 항목이 속한 법

#추출 코드 번역 GET /mapping/...

명세서 13_TO21DB매핑 시트를 근거로 번역합니다. 결과는 목록이고, 원소마다 근거 시트 행이 붙습니다.

"data": [{"sheet_row": 20, "sheet_cells": ["ACUTE_TOX", "4", "경구", "", "GHS000000", "", ""], "class_result_code": "GHS000000"}]
경로 입력 (추출 JSON 쪽) 결과에 붙는 값
/mapping/hazard?class_code=&category=&route_form=&effect= hazard.classes[] class_result_code
/mapping/pictogram/{code} GHS07 등 symbol
/mapping/signal-word/{code} 위험, 경고 sign_word
/mapping/property/{code} physchem[].prop_code property_id
/mapping/endpoint/{code} toxicity[]·ecotox[]의 endpoint div_codes (후보 여러 개)
/mapping/regulation/{code} regulations[].item_code regulate_item_id

hazard를 쓸 때 주의할 점:

  • category는 시트 값과 정확히 같아야 합니다. 구분이 있는 분류는 category를 꼭 줘야 결과가 나옵니다.
  • 시트가 route_form이나 effect로 나눈 분류는 그 값까지 같아야 합니다.
  • 분류 결과가 없는 경우는 class_code=(hazard.classified = false)로 찾습니다.

오류: class_code가 없으면 422, 모르는 종류면 404.

#일괄 대조 POST /lookup

추출 JSON(TO21 스키마) 한 건을 그대로 보내면, 그 안의 코드마다 번역 결과와 HTODB 원본을 돌려줍니다.

"data": [
  {"path": "msds[0].components[0].cas_no", "kind": "cas", "value": "0000-00-0", "seq": 1,
   "lookup_key": "0000-00-0", "chemicals": {"total": 1, "rows": ["..."]}, "details": {"classifications": "...", "...": "..."}},
  {"path": "msds[0].regulations[0].item_code", "kind": "regulation", "value": "NO_SUCH", "comp_ref": "1",
   "mapping": [], "reference": {}}
]
찾는 위치 (msds[i] 안) kind 붙는 결과

  • mapping: []이면 시트에 대응이 없다는 뜻입니다.

오류: JSON 모양이 틀리면 422이고, 틀린 경로를 알려 줍니다. 예: "추출 JSON 형식 오류: msds[0].hazard는 객체여야 함".

#parsed

parsed 목록의 각 원소는 셋 중 하나입니다.

  • null: 그 행에는 적용할 규칙이 없습니다.
  • {"rule": ..., "result": null}: 규칙은 있지만 값을 뽑지 못했습니다(자료 부족).
  • {"rule": ..., "result": {...}}: 뽑은 값입니다.
rule 대상 result
acute 급성독성 GHS0201~0205 {descriptor, sign, value, value_max, unit, species, basis}. 범위면 value가 최소값. 단위가 맞지 않으면 sign: "?"
aquatic_acute GHS0311~0314 {sign, value, unit: "mg/L"}
aquatic_chronic_noec GHS0325~0328 {value, unit: "mg/L"} ('=' NOEC 중 최소값)
rapid_degradability GHS0331 {rapidly_degradable: true/false}
STATE · PH · BOILING_POINT · FLASH_POINT · VISCOSITY_40 물성 항목 {value}. 성상은 "기체"·"액체"·"고체", 인화점은 최소값, 점도는 40℃ 동점도만

규칙의 세부 내용은 backend/src/msds/compliance/htodb/parsers.py에 있습니다.
